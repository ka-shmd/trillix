# trierra

[![CI](https://github.com/ka-shmd/trierra/actions/workflows/ci.yml/badge.svg)](https://github.com/ka-shmd/trierra/actions/workflows/ci.yml)

SaaS-конструктор форм (аналог Tally), MVP. Go (stdlib-first) + PostgreSQL 16 + React/TypeScript.
Монорепозиторий: Go-API в `cmd/` и `internal/`, кабинет в `web/app`, публичный рендерер в
`web/renderer`, миграции в `migrations/`, инфраструктура в `deploy/`.

Репозиторий: `github.com/ka-shmd/trierra` (он же module path).

Документация — в `docs/`: [ARCHITECTURE](docs/ARCHITECTURE.md) (как устроено и почему),
[DEV-PLAN](docs/DEV-PLAN.md) (что делаем и когда), [PROCESS](docs/PROCESS.md) (как работаем).
Справочники по реализованному: [API](docs/API.md) (эндпоинты, тела, коды ошибок),
[SCHEMA](docs/SCHEMA.md) (таблицы, ключи, индексы) — производные от кода, правятся вместе с ним.

## Требования

- Go 1.26+ (см. `go.mod`)
- Node.js 20+ и npm (фронты `web/app`, `web/renderer`; e2e — `e2e/`)
- Docker + Docker Compose (Postgres в dev; весь стек в prod-local)
- [golangci-lint](https://golangci-lint.run) v2 — для `make lint`

## Текущий статус

**Фаза 8.5 «Продуктовый минимум» завершена.** Слой между «технически работает» и «выбрали бы».
**Экран «после отправки»** — свой текст благодарности и redirect (оба валидируются на бэке: `javascript:`
и прочие схемы отбрасываются `ValidateSchema` даже в черновике — значение уходит в `window.location`).
**Четыре новых типа вопросов** — телефон (мягкая валидация: символы и число цифр, не формат страны),
выпадающий список, шкала (диапазон `0 ≤ min < max ≤ 10` — закрывает и 1–5, и NPS 0–10) и чекбокс-согласие;
все четыре кодируют ответ **строкой** — тип `Answer` не расширялся. **Сводка ответов** — распределения,
средние и доля заполнивших, агрегация на сервере (браузеру сырые ответы не выгружаются: 9999 ответов →
тело 666 Б); знаменатель — «сколько человек вопрос **видели**», а не общее число ответов. **Закрытие формы**
по дате и лимиту мест (`close_at`/`response_limit`/`closed_message`, миграция `0007`): лимит — жёсткий кап
ровно N под `pg_advisory_xact_lock`, закрытая форма отдаёт **410 «приём закрыт»**, а не 404 (инвариант 5
сузился до черновика — ADR §10). **Визиты, конверсия и воронка отвала** (`form_visits`, миграция `0008`,
модуль `internal/visits`): два бикона `sendBeacon` из рендерера, **без IP и без cookie**, конверсия по
`visitId`, а не делением двух счётчиков; на карточке — «N просмотров → M ответов (K %)», отдельным табом —
на каком вопросе уходят. **Поиск и сортировка на дашборде** (по имени, обновлению, созданию, числу ответов) —
один SQL-запрос на три порядка, порядок запечатан в курсоре. Экраны формы собраны в табы
(«Поделиться / Ответы / Сводка / Воронка») — маршруты, а не стейт, поэтому адресуются и переживают F5.
Перенесено в POST-MVP решением владельца: шаблоны форм (фаза 19) и embed + QR (фаза 20).
Как устроена аналитика и как её расширять — [docs/ANALYTICS.md](docs/ANALYTICS.md); контракт и таблицы —
[docs/API.md](docs/API.md) и [docs/SCHEMA.md](docs/SCHEMA.md).

**Фаза 8 «Полировка» завершена.** Пройтись руками и убрать трение: drag-and-drop блоков в билдере
(dnd-kit, ещё с фазы 6.5); **undo/redo** со стеком снапшотов и коалесингом текста (Ctrl+Z/Shift+Z);
пустые состояния и микро-UX — дружелюбный **app-level 404** и error-boundary кабинета
(`defaultNotFoundComponent`/`defaultErrorComponent`; 404 кабинета «мягкий» HTTP 200 из-за
SPA-fallback, настоящий 404 — на публичной `/r/{slug}`), фокус submit рендерера; **дубликация формы**
с дашборда с разъездом «внутреннее имя (`forms.name`) vs публичный заголовок (`forms.title`)» —
суффикс `«(копия N)»` (нумерация без коллизий) уходит только во внутреннее имя, публичный заголовок
остаётся чистым (ADR §10, миграция `0006`); страница формы `/r/{slug}` теперь строится из собранного
`index.html` рендерера (Go не перечисляет ассеты вручную — прод-only расхождений больше нет).
Снято решением владельца: тёмная тема рендерера и целенаправленный профайлинг производительности.
Контракт и таблицы — в [docs/API.md](docs/API.md) и [docs/SCHEMA.md](docs/SCHEMA.md).

**Фаза 7 «Prod-local: репетиция прода» завершена.** Весь прод-контур собирается и работает
локально: multi-stage distroless-образ Go (`deploy/Dockerfile`), `deploy/compose.prod.yml`
(postgres без порта наружу → одноразовые миграции → api → Caddy), `deploy/Caddyfile` с TLS от
локального CA на `app.localhost`/`f.localhost`. Одна команда `make prod-local` собирает образ и
статику фронтов и поднимает стек под https; `make prod-local-trust` доверяет локальному CA
(«замочек»). Прод-сборка фронтов — `scripts/build-static.sh`. Архитектурно: **две origin вместо
трёх** — кабинет и его API same-origin (без CORS), рендерер отдельным origin как граница
безопасности (ADR §10); CSRF усилена строгой проверкой `Origin`; заголовки безопасности (CSP,
nosniff, frame-options) в Caddy. Сквозной **Playwright-e2e** (`e2e/`) гоняет собранный продукт в
браузере против prod-local; релизный workflow по тегу `v*` кладёт образ в GHCR и статику в GitHub
Release. **При правке UI см. раздел «Прод-контур» в [web/CLAUDE.md](web/CLAUDE.md)** (dev прячет
прод-баги; CSP, e2e, Go-страница `/r/{slug}`).

**Фаза 6.5 «Редактор в стиле Tally» завершена.** Кабинет переведён на Tailwind CSS v4 + shadcn/ui:
сайдбар-навигация, единый вид дашборда, таблицы ответов и экранов auth. Сборка формы — slash-редактор как
документное полотно: название первой строкой, «/» открывает меню типов полей (в т.ч. на уже набранном
тексте — он становится подписью), клавиатурная навигация (Enter/Backspace/стрелки), перетаскивание блоков
(dnd-kit), инлайн-опции choice и инлайн-контролы `required`/`description` у блока. Добавлен неотвечаемый блок
`text`, форма-уровневые `submitLabel` (текст кнопки) и `settings.placeholder` (подсказка поля) — расширения
контракта Zod↔Go с тестами; единый вид формы вынесен в `web/shared/fields` (редактор ↔ превью ↔ рендерер не

## Быстрый старт

```sh
cp .env.dev .env    # активный .env (в .gitignore); .env.example документирует каждую переменную
make dev            # поднять Postgres и запустить API на хосте
```

Проверка в другом терминале:

```sh
curl localhost:8080/healthz
# {"status":"ok"}
```

## Фронтенды

Два отдельных Vite-проекта. Первый запуск — установить зависимости в каждом:

```sh
cd web/app      && npm install && npm run dev   # кабинет:  http://localhost:5173
cd web/renderer && npm install && npm run dev   # рендерер: http://localhost:5174
```

`web/app` проксирует `/api` на Go-сервер `:8080`, `web/renderer` — `/public` (в dev CORS не нужен).
Кабинет — вход, дашборд и slash-редактор форм; рендерер — публичная форма по `/r/{slug}`.

## Команды

`make help` — полный список. Основные:

| Цель            | Что делает                                             |
|-----------------|--------------------------------------------------------|
| `make dev`      | Поднять Postgres и запустить API                       |
| `make db-up`    | Поднять только Postgres в Docker                       |
| `make db-down`  | Погасить Postgres (данные остаются в volume `pg_data`) |
| `make migrate-up` / `make migrate-down` | Применить все миграции / откатить последнюю |
| `make test`     | Go (`-race`, вкл. интеграционные в testcontainers) + vitest обоих фронтов |
| `make lint`     | `golangci-lint run` + eslint/tsc обоих фронтов          |
| `make seed`     | Демо-данные: пользователь `demo@trierra.local` / `demo-password` + 60 форм |
| `make prod-local` | Репетиция прода: собрать образ + статику, поднять весь стек под https на `*.localhost`, smoke |
| `make prod-local-down` | Погасить prod-local (тома с данными остаются)      |
| `make prod-local-trust` | Доверить локальный CA Caddy — настоящий «замочек» (sudo) |

Раннер миграций встроен в бинарник: `api migrate up` / `api migrate down` (в проде — та же
init-команда). Остановка сервера — SIGINT/SIGTERM (Ctrl+C): активные запросы дорабатываются
(потолок 15 с).

### Прод-контур и e2e

Репетиция прода на своей машине (distroless-образ, Caddy, https):

```sh
cp .env.prod-local .env   # опционально; make prod-local и так берёт .env.prod-local
make prod-local           # собрать образ + статику, поднять стек; в конце — smoke
# https://app.localhost (кабинет) · https://f.localhost/r/{slug} (форма)
make prod-local-trust     # разово: доверить локальный CA Caddy → «замочек» (sudo)
```

Сквозной Playwright-e2e против поднятого prod-local (единственное, что проверяет **собранный**
продукт в браузере — ловит баги «прод ≠ dev»):

```sh
cd e2e && npm ci && npx playwright install chromium   # один раз
npm test
```

Подробности — [e2e/README.md](e2e/README.md). Гаси стек: `make prod-local-down`.

### Переменные окружения

| Переменная          | Обязательна | Описание                                                        |
|---------------------|-------------|-----------------------------------------------------------------|
| `HTTP_ADDR`         | да          | Адрес HTTP-сервера, напр. `127.0.0.1:8080`                       |
| `POSTGRES_USER`     | да          | Роль Postgres (читает compose при создании контейнера)          |
| `POSTGRES_PASSWORD` | да          | Пароль роли Postgres                                            |
| `POSTGRES_DB`       | да          | Имя базы Postgres                                               |
| `DATABASE_URL`      | да          | DSN подключения к БД (сервер и раннер миграций)                 |

Это подмножество для dev. **Полный список с описанием каждой переменной — в
[`.env.example`](.env.example)** (источник истины): туда входят `COOKIE_SECURE`,
`FORM_TOKEN_SECRET`, `PUBLIC_RENDERER_BASE_URL`/`_INDEX_PATH`, `OG_IMAGE_URL`,
`APP_ORIGIN` (CSRF), домены Caddy `APP_DOMAIN`/`RENDERER_DOMAIN` и build-time `VITE_PUBLIC_BASE_URL`.
Различия контуров живут только в значениях: `.env.dev` (http, localhost) vs `.env.prod-local`
(https, `*.localhost`, `COOKIE_SECURE=true`) — приложение одно, ветвления по контуру в коде нет.
