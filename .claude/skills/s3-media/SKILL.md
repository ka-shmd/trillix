# Объектное хранилище

**Читай `docs/S3.md` перед правкой.** Дизайн и обоснование — `docs/DESIGN-s3-media.md`,
ключевые решения — ARCHITECTURE ADR §10.

## Двухслойность — не оверинжиниринг, а следствие несовместимости политик

`internal/blob` — агностичный S3-клиент (ручной sigv4, без minio-go/AWS SDK: нужны только
Put/Delete, малая поверхность не оправдывает зависимость сверх замороженного списка).
`internal/media` — доменное хранилище картинок поверх него.

Объекты несовместимы по политикам: public-картинки, private-файлы ответов (Фаза 17), бэкапы.
Узкие интерфейсы **у потребителя** дают переиспользование без god-интерфейса.

## Что важно не сломать

- **Ключ в схеме, не URL.** В JSONB лежит `settings.imageKey`; абсолютный адрес собирается из
  `MEDIA_BASE_URL`. Так картинки переносимы между провайдерами.
- **Раздача same-origin через Caddy `/media/*`** — это даёт `img-src 'self'` и прячет endpoint.
  Upstream в env (`MEDIA_UPSTREAM`/`MEDIA_UPSTREAM_HOST`): prod-local → MinIO, прод → арендованное
  S3. Presigned-GET ломает кэш и `og:image` — не вводить.
- **Только PNG/JPEG** (stdlib декодит и жмёт без зависимостей). WebP/GIF нет: нет stdlib-энкодера.
- **`Presign`/`HeadObject`/`ListObjects` не реализованы** — нет потребителя. Добавляются вместе
  с первым, а не заранее.

## Известные границы

- **Осиротевшие объекты не собираются вообще** (TD-16): ключи контент-адресны, одну картинку
  могут делить несколько форм и версий, поэтому «удалить при удалении блока» снесло бы чужую.
  GC требует refcount и `blob.ListObjects`.
- **Черновиковые картинки публично читаемы** по неугадываемому hash-URL — модель Notion/Tally,
  инвариант 5 не нарушается (блоб не раскрывает существование формы).
- **На проде бакет открыт на чтение вручную**, `createbuckets` работает только с MinIO;
  регион `ru-1` выбран наугад и подтверждён только тем, что загрузка работает.
