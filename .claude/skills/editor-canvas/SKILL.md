# Полотно редактора

**Читай `docs/EDITOR.md` перед правкой** — здесь только то, что ломается чаще всего.
Источники истины выше справочника: ARCHITECTURE §3.4/§10 и DEV-PLAN фаза 8.7.

## Модель, которую легко нарушить

**Вопрос — это группа блоков, а не блок.** Блоки одной группы несут общий `groupId`, идут
подряд, и в группе не больше одного отвечаемого блока. `groupId` **выводится** функцией
`regroup` из раскладки, а не хранится руками.

Группа — ровно две сущности: «подпись…поле» (связь ищется **от поля вверх** через контент)
и голое поле. Всё остальное — одиночки. Одиночки дают границу дропа после каждого
standalone-блока; жадная группировка склеивала лэйаут-раны и запирала перетаскивание.

**Подпись владеет группой:** групповая ручка живёт на подписи мульти-группы, `trash` по
подписи сносит группу целиком.

## Два несущих решения dnd — не трогать вслепую

1. **Блочный слой — одна сортируемая вселенная.** Вложенные `SortableContext` всех групп
   получают ОБЩИЙ список `blockIds`. Нарезка items по группам ломает драг: over в чужом
   контексте → `overIndex −1` → dnd-kit гасит трансформы, элемент замирает под мышкой.
2. **`collisionDetection` фильтрует droppable'ы по слою активного** (группа → только группы,
   блок → только строки). Без фильтра `closestCenter` мечется между контейнером группы и
   строками — джиттер.

## Инварианты, которые проверяются не глазами

- **id отвечаемых блоков стабильны** — на них ссылаются `answers` и `form_visits.last_block_id`.
  Ни переименование, ни разложение вопроса связь не рвут.
- **Подпись для аналитики берётся из группы по `groupId`, не по позиции** — иначе
  перетаскивание молча переклеивает подпись на чужой инпут. Единая точка — `domain.QuestionOrder`.
- **Контрол, появляющийся по hover/фокусу, — только в absolute-кластер значков строки.**
  Занимающий место в потоке схлопывается на `mousedown`, всё ниже уезжает вверх, `mouseup`
  приходит мимо цели, и клик молча теряется (TD-22).

## Правя полотно

Контракт двусторонний: тип блока меняется синхронно в Go (`internal/domain/schema.go`,
предикаты `isCaption`/`carriesText`/`isContent`) и Zod (`web/shared/entities/formSchema.ts`),
**в одном PR, с тестами обеих сторон**. Новый тип добавляется в предикат, а не в цепочку
`if type == …`: забытая ветка не падает, а молча трактует тип как соседний.

Вид поля — в `web/shared/fields/fields.css` (`rf-*`), его надевают три поверхности
(редактор, превью, рендерер). Tailwind в `@fields` не тащить — сломает бюджет рендерера.

Открытая отложенная полировка — TD-26 (клавиатура на строках-полях, подсказки «добавить
заголовок/поле»), известные дефекты — TD-30, TD-31, TD-32, TD-33.
