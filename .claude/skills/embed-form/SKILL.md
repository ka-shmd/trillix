# Встраивание формы в чужие сайты

**Читай `docs/EMBED.md` перед правкой.** Замысел и отвергнутые альтернативы —
`docs/design/embed.md`, ключевые решения — ARCHITECTURE ADR §10 (четыре строки фазы 20).

## Одна форма, один фрейм, три оболочки

Блок, виджет и страница — это `/r/{slug}` в `<iframe>` с разным `?embed=` и разной обвязкой на
хост-странице. **Рендер формы прямо в DOM чужой страницы запрещён ADR:** это четвёртая
поверхность вида поверх трёх на `@fields` плюс власть чужих CSS-ресетов и CSP над формой.

Код по разные стороны границы: `web/renderer/src/features/form/embed.ts` — внутри фрейма
(бюджет формы 60 КиБ), `web/renderer/embed/` — на чужой странице (**свой** бюджет 4 КиБ,
каталог вне `src/` намеренно: один импорт `zod`/`@fields` его разносит).

## Что важно не сломать

- **`/embed/v1.js` — бессрочный контракт.** Файл вставлен в чужие страницы, отозвать нельзя:
  только обратно совместимые правки, ломающее изменение = `v2.js`. Кэш `max-age=600`, никогда
  не `immutable` (имя без хеша).
- **Высота меряется по `body`, не по `documentElement`:** у `<html>` она не меньше вьюпорта
  фрейма, и раз выросший фрейм не уменьшится никогда.
- **Входящее `message` проверяется дважды** — `event.origin` и форма полезной нагрузки
  (`readFrameMessage`). На чужой странице в `message` летит трафик чатов и расширений.
  Свой фрейм узнаётся по `event.source === iframe.contentWindow`.
- **Ответы через границу фрейма не уезжают.** `submit` несёт только `submissionId`.
- **Стили в загрузчике — только через CSSOM** (`el.style.x = …`): атрибут `style` отбрасывается
  строгой CSP чужого сайта.
- **Фрейм виджета создаётся при первом открытии**, не заранее: иначе визит засчитывается
  каждому зашедшему на сайт и конверсия считается от посетителей сайта.
- **Предзаполнение адресуется id блока** (`pf.<id>`), ложится **под** черновик ответов, полей
  не создаёт и подтверждением значения не является. `name` вопроса ключом брать нельзя.
- **Настройки вставки не хранятся на сервере** — только data-атрибуты сниппета (ADR).

## Заголовки — единственное место, которого dev не видит

`frame-ancestors *` и снятый `X-Frame-Options` действуют **точечно на `/r/*`**; кабинет
остаётся `DENY` + `'none'` на всех путях. В dev CSP нет вовсе, поэтому ошибка здесь видна
только на prod-local (`curl -kI`) и в `e2e/tests/embed.spec.ts`. После правки Caddyfile помни
TD-27: зелёный деплой ≠ применившийся конфиг.

## Проверка

Юнитами покрыто чистое — разбор атрибутов, адрес фрейма, разбор сообщений, сборка сниппета.
DOM-часть (модалка, ловушка фокуса, авторесайз) живёт только в e2e-сценарии `embed`, который
требует поднятого prod-local. Проверять надо **отправку ответа из фрейма**, а не факт загрузки:
заголовки ломаются именно на ней.
