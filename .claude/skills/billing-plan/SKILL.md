# Тарифы и лимиты

**Читай `docs/BILLING.md` перед правкой.** Почему принято именно так — `docs/DESIGN-billing.md`,
ключевые решения — ARCHITECTURE ADR §10, правила Go-зоны — `internal/CLAUDE.md`.

**Денег система не принимает.** Платёжного провайдера, вебхуков, автосписаний и чеков нет —
отдельная будущая фаза. Сегодня план воркспейса меняется операцией в БД.

## Три уровня, которые нельзя слипать

| Что | Где | Цена изменения |
|---|---|---|
| какие гейты бывают | `internal/entitlements/catalog.go` | строка + деплой |
| что даёт план | `plans.limits` (данные) | `UPDATE`, **без деплоя** |
| где гейт применяется | вызов `Check*` в сервис-методе | строка + деплой |

`if plan == "…"` вне `internal/entitlements` **запрещён** — сторожит `make check-docs`.
Открыть возможность всем = один `UPDATE`; вызов `Check*` остаётся выключателем обратно.

## Что нельзя путать: квота тарифа и кап формы

**Кап формы** (`forms.response_limit`) ставит владелец, он **закрывает приём** (410).
**Квота тарифа** не закрывает ничего: ответ принимается ВСЕГДА, сверхлимитная строка
помечается `over_quota` и скрывается только в кабинете владельца. Отказ респонденту по
причине неоплаты владельцем — потеря данных клиента, а не «логичная связка».
Статус подписки не закрывает форму ни при каком значении.

## Правила, нарушение которых даёт тихо неверный результат

- **Молчание плана про известный ключ — ошибка, а не «разрешено»** (`TestPlansCoverCatalog`).
  `null` = безлимит, `0` = запрещено всё; это разные вещи.
- **Порядок обязателен: сначала авторизация, потом тариф.** Иначе код ответа (404 против 402)
  рассказывает постороннему о существовании чужой формы и о плане чужого воркспейса.
- **Аналитика собирается всем, гейтится ЧТЕНИЕ.** Не собирать бесплатным = показывать пустоту
  в момент апселла.
- **Ошибка `Check*` = «спросить не удалось», а не «нельзя».** Приём ответа при ней пропускает
  ответ как «в пределах квоты» и логирует; чтение отдаёт 500.
- **Новый фильтр `NOT over_quota` — обойди всех потребителей числа**: список, CSV, сводка,
  счётчик карточки формы. Счётчик капа формы фильтр НЕ применяет.
- **Период — календарный месяц по Москве** (FixedZone, не LoadLocation: tzdata в scratch-образе
  нет) и едет **в самом решении** (`Decision.Period`). Не вычисляй его у вызывающего заново:
  два чтения часов расходятся на границе месяца, и расход уезжает в закрытый период — беззвучно
  и раз в месяц.
- **Новый фильтр по колонке — проверь план `EXPLAIN`ом на сидированной базе.** `over_quota` не
  было ни в одном индексе, и счётчики кабинета ушли из index-only в скан кучи (миграция 0015).

## Добавить возможность в платный тариф — три шага

1. `catalog.go`: константа + строка в `Catalog` + строка в `CatalogOrder`.
2. Миграция: `UPDATE plans SET limits = limits || '{"ключ": …}'` для **каждого** плана.
3. Вызов `CheckWorkspace` в сервис-методе; для чтения отказ — `domain.ErrPlanRequired` (402).

Потребитель объявляет свой узкий интерфейс `Plans`, а не импортирует сервис целиком.
