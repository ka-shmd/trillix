# Ассистент над формой

**Читай `docs/AI.md` перед правкой** — здесь только то, что ломается чаще всего.
Решения — ADR §10 `ARCHITECTURE.md`, план и замеры — `DEV-PLAN.md` фаза 26.

## Инвариант, который нельзя снять правкой кода

**Ответы респондентов и аналитика в модель не уезжают.** Наружу едет текст автора и
структура его собственной формы. Это не осторожность, а обработка ПДн по поручению
владельца формы: снятие — новая строка ADR вместе с российским провайдером, согласием
и правкой политики. Родня в очереди — «AI-сводка по свободному тексту»;
**снимая ограничение там, не снимай его здесь.**

Сторож — тест на `ai.Fake`: он записывает запросы, и по ним проверяется содержимое.

## Четыре вещи, которые ломаются тихо

1. **Перевыпуск `blk_*`/`opt_*` при правке** обнуляет аналитику молча: на них
   ссылаются ответы, сводка и воронка. Поэтому правка идёт ОПЕРАЦИЯМИ поверх
   документа, а не пересборкой из плана — пересборка заодно теряет плейсхолдеры, имя
   вопроса, класс, настройки файла и страниц, логику и картинки.
2. **Порядок добавлений.** Несколько `add` с одним `after` обязаны сохранить порядок:
   применение помнит, куда легло предыдущее. Иначе сборка с нуля (десяток `add` с
   пустым `after`) переворачивает форму.
3. **Инструкция.** Что не попало в списки правок — не произошло, даже если модель
   написала в `reply`, что сделала. Меняешь промпт — проверь живым вызовом сборку с
   нуля, правку и вопрос: инструкция, написанная только про правку, давала пустой
   результат с бодрым рапортом.
4. **`AI_MODEL` и `AI_REASONING_EFFORT` — сцепка.** Набор значений усилия у каждой
   модели свой; неверное валит генерацию целиком (400 на каждый запрос), а не
   деградирует. `qwen3.6` понимает `none`, `gpt-oss-20b` — только `low|medium|high`.
   Меняешь модель — проверь усилие одним запросом.

## Где что живёт

| Правишь | Файл |
|---|---|
| вызов модели, ретраи, починку | `internal/ai/` (про формы не знает) |
| словарь типов для модели | `domain/formplan.go` (`planKinds` — растёт от новых типов вопросов) |
| проекцию формы и операции правки | `domain/formedit.go` |
| промпт, намерения, квоту, гейт оформления | `internal/forms/chat.go` |
| шторку, ленту, историю разговора | `web/app/src/features/forms/chat/` |

**Новый тип вопроса** — строка в `planKinds`, и тест по `blockTypes` не даст забыть:
у каждого отвечаемого типа обязана быть запись либо причина в `planExcluded`.

**Гейт оформления** спрашивается ДО вызова модели, а платное отсекается на ответе:
модель указание про тариф нарушает (замер), поэтому решает сервер.

## Проверять живым вызовом — три сценария

Сборка с нуля, правка существующей формы, вопрос о форме. Сетевых вызовов в тестах
проекта нет (модель подменяется `ai.Fake`), поэтому качество промпта проверяется
только руками — и только этими тремя.
