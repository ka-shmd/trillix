# Пространства, роли и приглашения

**Читай `docs/WORKSPACES.md` перед правкой.** Почему принято именно так — ADR §10
(строки про субъект подписки, заморозку и «право спрашивается по действию»);
тарифы как таковые — `docs/BILLING.md` (скилл `billing-plan`).

## Три правила, которые нарушают чаще всего

1. **Спрашивай действие, а не роль.** `Can(ctx, wsID, userID, domain.ActionFormDelete)`.
   `role == "owner"` вне `internal/workspaces` запрещён — сторожит `make check-docs`.
   Причина: персональные исключения прав должны приезжать внутрь `Can`, не трогая
   десятки точек вызова.
2. **Не участник → 404, участник без права → 403.** Первое скрывает существование
   чужого пространства (инвариант 5), второе — нет, и путать их нельзя.
3. **Лимит `workspaces` считает пространства во ВЛАДЕНИИ, а не членства.** Иначе
   владелец Pro не сможет позвать никого с Free — а звать он будет именно их.

## Куда лезть при типовых задачах

| Задача | Точки правки |
|---|---|
| новое действие в правах | `domain.Action` → `roleActions` + `AllActions` в `internal/workspaces/access.go` → вызов `Can` в сервисе → тест ячейки |
| новая роль | те же + `CHECK` в `0017` (приглашать владельцем нельзя) + матрица построчно |
| новый гейт тарифа | `internal/entitlements/catalog.go` + `plans.limits` (миграция) + вызов `Check*`; см. `billing-plan` |
| экран, зависящий от прав | прячь по `permissions` из `GET /workspaces/{id}/members`, не по роли на фронте |

## Что легко сломать

- **Владелец ровно один.** Держат частичный уникальный индекс (не больше) и SQL
  `DELETE … AND role <> 'owner'` (не меньше). Убери условие из запроса — владелец
  снимет сам себя, и пространство останется без плана.
- **Личное пространство** опознаётся `personal_user_id`, а не «самым ранним членством».
  Оно не удаляется, не покидается и **не замораживается**.
- **Заморозка стоит в `Can`** и потому стоит второго запроса к БД на каждую проверку —
  это осознанная цена, а не недосмотр. Публичный приём ответов через `Can` не ходит и
  замораживаться не должен **никогда**: отказ респонденту теряет данные клиента.
- **Приглашение и письмо — одной транзакцией.** Разведёшь — получишь ссылку без письма
  либо письмо без ссылки.
