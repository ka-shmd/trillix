# Интерфейс кабинета

**Читай `docs/DESIGN-SYSTEM.md` перед правкой экрана** — там порядок сборки, шкала,
ритм, токены и разбор граблей. Правило «весь кабинет — на shadcn, свой контрол это
отступление» — в `web/CLAUDE.md`. Полотно формы и общий вид полей системе не
подчиняются: это скиллы `editor-canvas` и `form-field`.

## Порядок сборки экрана

`PageContainer` (одна из трёх ширин) → `PageCrumbs` (обязательны) → `PageActions` →
`PageHeader` → `Section` на каждый блок → `LoadingRows`/`ErrorState`/`EmptyState`.
Экран без нарисованного отказа не готов.

## Четыре правила, которые нарушают чаще всего

1. **Экран не рисует свою шапку и свою колонку.** Верхний бар один на приложение;
   литеральный `max-w-*`, рукописная коробка отказа и «Загрузка…» абзацем — то, из-за
   чего кабинет и выглядел собранным из разных приложений.
2. **Кегли заморожены.** 30/800 → 20/700 → 16/600 → 16/400 → 14/600 (подпись поля) →
   14/400 → 12/500 (крошки). Нужен размер вне таблицы — это разговор, а не правка
   класса: промежуточный кегль виден именно тем, что ни с чем не рифмуется.
3. **Цвет — только токеном, и у цвета есть РОЛЬ.** `--primary` = «сюда можно нажать»,
   `--success`/`--warning`/`--destructive` = состояние, `--highlight` (фиолетовый) =
   деталь и ничего не значит, `--utility` = чёрная служебная кнопка. Покрасил деталь
   синим — синий перестал быть обещанием; покрасил кнопку фиолетовым — обещания нет
   вовсе. Новый токен заводится сразу с парой в `.dark`; контраст меряется пикселями.
4. **Действия строки считаются по числу и частоте.** Два-три частых — иконками в
   строке, много или редкие — в меню «⋯». Деструктивное отделяется в обоих случаях.

## Куда лезть при типовых задачах

| Задача | Точки правки |
|---|---|
| новый экран кабинета | маршрут в `routes/_app/` → примитивы `shared/page/` в порядке выше |
| перевести старый экран | заменить `div.mx-auto.max-w-*` на `PageContainer`, заголовок на `PageHeader`, блоки на `Section`, коробку `border-destructive/40` на `ErrorState`; смысл экрана не трогать |
| новый цвет или статус | токен в `web/app/src/index.css` (обе темы) → регистрация в `@theme inline` → использование утилитой |
| пункт навигации | `features/app-shell/AppSidebar.tsx`, ярус по уровню: работа / контекст / аккаунт |
| логотип сервиса | инлайн-SVG в фиче (`features/integrations/ServiceIcon.tsx`); CSP режет чужие хосты |
| иллюстрация, схема | инлайн-SVG, залитый `--highlight` с прозрачностью (`fill-highlight/25`); образец — `features/forms/EmbedModeArt.tsx` |
| кнопка «копировать», «скачать» у поля | `Button variant="utility"` — локальный вариант, чёрная |

## Что легко сломать

- **Вендоренных правок две: вариант `utility` у `Button` и вес у `Label`.**
  Переустановка компонента из shadcn сотрёт обе; в файлах об этом сказано.
- **Размер вендоренного компонента правится ТЕМ ЖЕ вариантом**, каким задан:
  `has-[>svg]:px-2`, `data-[size=default]:h-10`, `md:text-base`. Плоская утилита молча
  не сработает.
- **`hover:bg-transparent` не гасит `dark:hover:bg-accent/50`** — тёмный вариант
  специфичнее и вернёт подложку при включении темы.
- **`Switch`: ход бегунка привязан к его ширине** (`calc(100%-2px)`) — меняешь дорожку,
  пересчитывай сдвиг явно.
- **Ряд контролов ровняется по нарисованному:** у ghost-кнопки граница — текст, у
  залитой — край заливки, поэтому равный `gap` даёт разные зазоры на глаз.
- **Радиксовое меню в тестах открывается Enter'ом на триггере**, а не `fireEvent.click`.
- **Крошка пространства берётся из адреса** — форма своего пространства не знает
  (`workspaceId` нет в API). Это известный дефект, а не повод чинить крошку.
