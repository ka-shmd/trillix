# Интерфейс кабинета

**Читай `docs/DESIGN-SYSTEM.md` перед правкой экрана.** Правило «весь кабинет — на
shadcn, кастом только на полотне формы» — в `web/CLAUDE.md`; полотно и общий вид
полей — скиллы `editor-canvas` и `form-field`, эта система их не касается.

## Четыре правила, которые нарушают чаще всего

1. **Экран не рисует свою шапку.** Верхний бар один на приложение; путь идёт в
   `PageCrumbs`, кнопки — в `PageActions`. Крошки обязаны быть у **каждого** экрана:
   пустой бар — полоса с разделителем, которая не сообщает ничего.
2. **Контейнер, заголовок, ошибка и пусто берутся из `shared/page/`.** Литеральный
   `max-w-*`, рукописная коробка отказа и «Загрузка…» абзацем — то, из-за чего
   кабинет и выглядел собранным из разных приложений.
3. **Цвет — только токеном.** `bg-emerald-500` в разметке не имеет тёмного значения;
   новый токен заводится сразу с парой в `.dark`.
4. **Действия строки считаются по числу и частоте.** Два-три частых — иконками прямо
   в строке; много или редкие — в меню «⋯». Деструктивное в обоих случаях отделяется.

## Куда лезть при типовых задачах

| Задача | Точки правки |
|---|---|
| новый экран кабинета | маршрут в `routes/_app/` → `PageContainer` + `PageCrumbs` → `PageHeader`/`Section` → состояния из `shared/page/states.tsx` |
| новый цвет или статус | токен в `web/app/src/index.css` (обе темы) → регистрация в `@theme inline` → использование утилитой |
| пункт навигации | `features/app-shell/AppSidebar.tsx`, ярус выбирается по уровню (работа / контекст / аккаунт) |
| действия строки списка | иконки в строке (образец — связка на экране интеграций) либо `DropdownMenu` «⋯» (пространство в сайдбаре, карточка формы) |
| логотип сервиса | инлайн-SVG в фиче (`features/integrations/ServiceIcon.tsx`); CSP режет чужие хосты |
| новый вендоренный компонент | `src/components/ui/`, зонтичный `radix-ui` уже установлен — это **не** новая зависимость |

## Что легко сломать

- **`PageCrumbs`: последний элемент — текущая страница**, ссылкой не бывает;
  остальные передаются готовыми `<Link>` роутера.
- **Крошки доводят до сущности, а не до раздела** — иначе путь дублирует табы.
- **Корневая крошка — пространство из адреса.** Форма своего пространства не знает
  (`workspaceId` нет в API), поэтому прямая ссылка без `?w=` покажет личное. Это
  известный дефект, а не повод чинить крошку.
- **Радиксовое меню в тестах открывается Enter'ом на триггере**, а не
  `fireEvent.click`: Radix слушает `pointerdown`.
- **Взаимоисключающие Tailwind-утилиты** (`border-transparent` / `border-primary`)
  молча решаются порядком в сгенерированном CSS — разводить наборы, а не
  «перебивать»; проверять computed-стилем.
