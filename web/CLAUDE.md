# Конвенции фронтенда (web/app, web/renderer)

## Зависимости — заморожены

**Кабинет (`web/app`):** react, tanstack (router/query), zod, zustand, dnd-kit (перетаскивание блоков в редакторе; подтянут в фазе 6.5), и — с фазы 6.5 — UI-слой на **Tailwind CSS v4 + shadcn/ui** (Radix-примитивы, class-variance-authority, tailwind-merge, clsx, lucide-react). Вендоренные shadcn-компоненты живут в `src/components/ui/` (линт-правила fast-refresh/purity там погашены — это чужой генератор, не наш стиль); хелпер `cn` — в `src/lib/utils.ts`; алиас `@/*` → `src/*`. Дизайн-токены — в неймспейсе shadcn в `src/index.css` (бренд-синий = `--primary`).

**Рендерер (`web/renderer`):** строго react + zod + общие entities. Tailwind и shadcn туда **запрещены** — они ломают бюджет бандла (95 КиБ gzip). Общие компоненты полей `@fields/*` используются обоими приложениями, поэтому **не переводятся на Tailwind** — сохраняют `rf-*` CSS-классы.

**Единый вид формы — `web/shared/fields/fields.css`.** Это единственный визуальный язык (раскладка `rf-page`, заголовок `rf-title`, вопрос `rf-label`/`rf-text`, поле `rf-input`, глифы выбора `rf-mark`, кнопка отправки `rf-submit`, токены `--rf-*`), который надевают **все три** поверхности: (1) редактор — `BlockRow`/`SlashEditor` навешивают `rf-*` поверх своего layout/dnd на Tailwind; (2) превью билдера (`PreviewPane` рисует заголовок+поля+кнопку); (3) публичный рендерер (`FormView`). Импортируется в `main.tsx` обоих фронтов после `index.css`. **Источник истины вида — форма в режиме редактирования**; значения `rf-*` = токены/утилиты shadcn-редактора, но в plain-CSS (рендерер читает без Tailwind). Правишь вид поля — правь `fields.css`, и три поверхности едут вместе; не заводи Tailwind-вид полей в `BlockRow` (только layout/взаимодействие) и не тащи Tailwind в `@fields`. Приложение может переопределить `--rf-*` (напр. кабинет в `.dark`).

**Как расширять полотно формы (добавить тип поля/элемент/стиль) — [`web/shared/fields/README.md`](shared/fields/README.md):** точки расширения по всему срезу, тонкости синхронизации (холст `rf-page` ↔ Tailwind-брейкпоинт редактора, глифы `rf-mark`, заголовок-`textarea`, `title` вне схемы), способ проверки. Читать перед правкой полей.

Добавление любой зависимости сверх перечисленного — только через вопрос человеку.

**Конфликтующие Tailwind-утилиты на одном элементе — молчаливый баг.** У `border-transparent` и `border-primary` (как и у `text-muted-foreground`/`text-foreground`) одинаковая специфичность: побеждает не та, что позже в строке `className`, а та, что позже в сгенерированном CSS. Поэтому «базовый класс + перебивка сверху» не работает: класс на элементе есть, вида нет. Либо разводи взаимоисключающие наборы (у `Link` роутера — `activeProps`/`inactiveProps`, образец — табы в `routes/_app/forms.$slug._manage.tsx`), либо сливай через `cn` (`src/lib/utils.ts`, там tailwind-merge и умеет разрешать конфликт). **Проверяется только computed-стилем** (`getComputedStyle`), наличие класса в `className` этот баг не ловит.

## Разделение стейта — главный закон

Серверные данные живут только в TanStack Query (никакого копирования ответов API в useState/zustand «для удобства»). Стейт билдера живёт только в zustand-сторе. Локальный UI-стейт (открыт ли дропдаун) — useState. Если непонятно, куда положить стейт: «переживает ли он перезагрузку страницы?» (да → Query) и «нужен ли он больше чем одному дереву компонентов?» (да → стор, нет → useState).

## Типы

Zod-схемы в `entities` — единственный источник типов домена; TS-типы выводятся через `z.infer`, дублирование интерфейсов руками запрещено. Каждый ответ API парсится Zod-схемой на границе (в api-клиенте), внутрь приложения непровалидированные `any` не проходят. Изменение Zod-схемы формы = изменение контракта → обязательно синхронное изменение Go-типов и `ValidateSchema`, в одном PR, с тестами обеих сторон.

## Структура

Feature-sliced: маршрут в `routes/`, логика и компоненты фичи в `features/<имя>/`, переиспользуемое между фичами — в `shared/`, доменные типы — в `entities/`. Импорты направлены вниз (`features → entities → shared`); импорт одной фичи из другой запрещён — общее выносится в entities/shared.

Маршруты в `web/app` — file-based (плагин `@tanstack/router-plugin` в `vite.config.ts`): дерево генерируется в `src/routeTree.gen.ts`, который **коммитится** (нужен для `tsc -b` в CI) и обновляется на каждом dev/build; в eslint для `src/routes/**` выключен `react-refresh/only-export-components` — роут-файлы обязаны экспортировать `Route`. Layout-группы через pathless-маршруты (`_auth`, `_app`), гард сессии — в `beforeLoad` через `context.queryClient` (см. `routes/_app.tsx` — эталон).

## Мутации

Каждая мутация обязана инвалидировать или патчить затронутые query-ключи — забытая инвалидация это баг, а не мелочь. Query-ключи — только через фабрику ключей фичи (`formKeys.list()`, `formKeys.detail(id)`), строковые литералы ключей в компонентах запрещены.

## Рендерер — особый режим

`web/renderer` — зона жёсткой экономии: перед добавлением кода туда проверить влияние на бандл (`npm run build`; CI-бюджет — **95 КиБ gzip JS**, проверяется `npm run check:bundle`, порог в `scripts/check-bundle.mjs`; поднят выше исходных 60 КБ, т.к. React+react-dom+zod съедают ~78 КиБ сами). Никакого роутера (slug из pathname) и TanStack Query, стейт — `useReducer`. Компоненты полей — общие с превью билдера, разъезжаться им нельзя: правишь поле — проверь оба места.

### HTML-оболочка формы: как устроена и что с ней можно

Страницу формы `/r/{slug}` в проде отдаёт Go, но **собирает её из твоего `web/renderer/index.html`** (паттерн vite-SSR template-replace): читает собранный `dist/index.html` и заменяет плейсхолдер `<!--og-meta-->` на OG-мету формы (title/description/og:*, серверные — зависят от формы). Всё остальное в `<head>` — твоё: `<meta>`, favicon, а `<script>`/`<link>` на ассеты впрыскивает vite. Go ассеты **не перечисляет** — что собрал vite, то и отдал.

Из этого — правила работы с оболочкой:

- **Добавляй ассеты сборки свободно.** Новый чанк (code-split), веб-шрифт с `<link rel="preload">`, favicon-манифест, модульный preload — Go про них знать не нужно, они приедут из собранного HTML сами. Раньше (до фазы 8) такой ассет ломал прод молча — теперь нет.
- **Не удаляй `<!--og-meta-->`** из `web/renderer/index.html`. Это точка вставки серверной меты; без неё api падает на старте (fail-fast). `<title>`/`<meta name="description">` для формы держит сервер — в исходный `index.html` их не возвращай (будет дубль).
- **Имена ассетов — дефолтные хеши** (`assets/index-[hash].js/css`), не задавай стабильные (`entryFileNames` и т.п.): они уезжают под `/assets/*` → immutable-кэш Caddy. Хеш меняется свободно — Go его не знает.
- **Статику рендерера в проде видит и api** (read-only mount `/srv/renderer`, `deploy/compose.prod.yml`): оттуда Go читает `index.html`. Тот же том раздаёт Caddy, поэтому HTML и ассеты всегда из одной сборки.
- **CSP-ограничение остаётся:** любой внешний источник (шрифт с чужого хоста, CDN) прод молча режет — см. «Прод-контур» ниже. Ассет должен быть свой, из сборки.
- **В dev `/r` отдаёт vite-dev** (собранного HTML нет), Go его не регистрирует — проверять страницу формы с OG-метой можно только на `make prod-local`.

## Доступность и UX-минимум

Интерактивные элементы — настоящие `<button>`/`<a>`, не div с onClick. У инпутов — label. Состояния loading/error/empty обязательны у каждого экрана с данными: экран, у которого не нарисован error-стейт, не готов.

**Глобальные fallback'и кабинета — в `createRouter` (`main.tsx`), не по маршрутам:** `defaultNotFoundComponent` (`shared/NotFound.tsx`) на неизвестный URL и `defaultErrorComponent` (`shared/ErrorScreen.tsx`, `reset` перезапускает маршрут) на краш лоадера/рендера. Оба полностраничные (могут сработать вне оболочки `_app`). Это дружелюбный дефолт на всё дерево — per-route error-стейты (запросы данных) он не заменяет, а страхует непойманное.

**Про HTTP-коды 404/ошибок кабинета — они «мягкие» (HTTP 200).** Клиентский роутинг + SPA-fallback Caddy (`try_files → index.html`) отдают 200, «404» рисует клиент; настоящий 404 требовал бы дублировать таблицу роутов на сервере — сознательно не делаем (стандарт для кабинета за логином, не индексируется). Где HTTP-код **важен** — публичная страница формы `/r/{slug}`: там Go отдаёт **настоящий 404** для **черновика/несуществующей** (`PublicForm → ErrNotFound → respond.go`), её читают краулеры. **Закрытая форма — не 404** (фаза 8.5 шаг 4, решение владельца): `/r` отдаёт тот же SPA-шелл (200), а JSON-ручка `GET /public/v1/forms/{slug}` — `410` c `{title, closedMessage}`; клиент рендерера рисует «приём закрыт». Форма была публичной, её существование не скрываем — инвариант 5 остаётся только для черновика.

## Прод-контур: что dev не показывает (фаза 7)

Dev (vite-dev) прощает то, что ломается только в прод-сборке за Caddy. Правя UI, держи в голове:

- **Проверяй против прод-сборки, а не только dev.** `make prod-local` поднимает настоящую прод-сборку (distroless-образ, Caddy, https на `app.localhost`/`f.localhost`); только там видны баги «прод ≠ dev». В фазе 7 так всплыли: форма без entry-скрипта (пустая) и без стилей (dev инжектит их через JS, прод — отдельными файлами).
- **E2e существует — гоняй после изменений UI.** `e2e/` — два Playwright-сценария против `make prod-local`: `full-loop` (регистрация → билдер → публикация → ответ → таблица → CSV) и `visits-funnel` (визит биконом под прод-CSP → конверсия на карточке → воронка → 410 на закрытой форме). Правки разметки/текста кнопок/лейблов ломают их селекторы — прогони `cd e2e && npm test` (нужен поднятый prod-local). В CI — `.github/workflows/e2e.yml` (nightly/по кнопке, не на каждый PR). **`full-loop` сейчас красный не из-за аналитики — TD-22.**
- **Бикон визита виден только на prod-local.** `navigator.sendBeacon` подчиняется `connect-src 'self'`, и заблокированный бикон **не бросает исключения и молчит в консоли** — счётчик просто остаётся нулевым. В dev CSP нет вовсе, поэтому единственная проверка — `visits-funnel.spec.ts`: ненулевой «1 просмотр» на карточке и есть доказательство, что бикон прошёл. Трогаешь адрес ручки визитов, Caddyfile или CSP — прогони этот сценарий.
- **CSP в проде строгая (`deploy/Caddyfile`), в dev её нет.** Любой **внешний** ресурс — веб-шрифт, картинка с чужого хоста, CDN-скрипт, `fetch` на другой origin — в проде **молча блокируется** (`default-src 'self'`). Нужен внешний источник → добавь его в CSP Caddyfile и проверь `curl -I` + e2e. `script-src` держим `'self'` (бандлы без inline-скриптов — не заводи их); инлайн-`style` разрешён (`'unsafe-inline'`).
- **Страницу формы `/r/{slug}` Go строит из собранного `index.html` рендерера** (не из рукописного шаблона) — поэтому новый ассет сборки правок Go не требует и прод-only поломок больше не даёт. Детали и правила работы с оболочкой — в разделе «HTML-оболочка формы» выше. Проверять OG-мету формы можно только на `make prod-local` (в dev `/r` отдаёт vite-dev).
- **API кабинета — относительный `/api` (same-origin), без CORS** (две origin, ADR §10). Не вводи кросс-origin-запросы: `connect-src 'self'` их и так заблокирует. Мутации несут `Origin` кабинета — его строго проверяет CSRF (`APP_ORIGIN`).
