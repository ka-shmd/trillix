# E2e (Playwright) — сквозной smoke против prod-local

Гоняет **собранный** продукт в реальном браузере — ловит класс багов «прод-сборка ≠
dev» (пустая форма без entry-скрипта, форма без стилей, бикон, зарезанный CSP),
которые не видят ни Go-, ни vitest-тесты.

Четыре сценария, намеренно раздельные — у каждого свой предмет, и падение сразу
называет подсистему, а не «что-то в проде»:

- **`full-loop`** (ARCHITECTURE §8) — регистрация → сборка формы слэш-редактором и
  диалогом типов → публикация → ответ с мобильного вьюпорта → таблица → CSV.
  Ходит через билдер **мышью**; сюда же добавляются новые типы вопросов
  (шкала и согласие — фаза 8.5 шаг 2), потому что DoD требует от них полного цикла.
- **`builder-keyboard`** — сквозной критерий фазы 13: форма собирается **одной
  клавиатурой** (Enter из названия → «/» с фильтром → `Mod+Alt+→` в ряд → `Mod+Enter`
  к вариантам) → публикация → ответ респондента; ряд из двух вопросов проверяется на
  полотне, у респондента на десктопе и столбиком на телефоне. Форма создаётся через
  API: предмет сценария — полотно, а не кнопка «Новая форма».
- **`form-settings`** — свой текст благодарности и лимит мест (фаза 8.5 шаги 1 и 4):
  второй респондент упирается в «приём закрыт». Форма собирается через API.
- **`visits-funnel`** — визит биконом под прод-CSP, конверсия на карточке, воронка,
  `410` на закрытой форме (фаза 8.5 шаги 6 и 6б). Форма собирается через API.

Правило разделения: через билдер ходят только `full-loop` (мышью) и
`builder-keyboard` (клавиатурой). Остальные строят форму запросами к API — иначе
каждая правка редактора красила бы в красный тесты, которые про редактор ничего не
проверяют.

**Регистрация под rate-limit'ом, и запас исчерпан** (`registerBurst = 3`, пополнение
~1 токен / 30 с, `cmd/api/main.go`). Три старых сценария регистрируют свой аккаунт
через UI и расходуют бурст ровно в ноль: холодный прогон сюиты проходит, а
**повторный запуск в течение ~1,5 минут упрётся в 429 и упадёт на шаге регистрации**
— с виду «тест сломался», хотя сломался лимитер по IP. Лимит не ослабляется ради
тестов (инвариант 6): просто подождать.

**Пятому сценарию регистрироваться уже нельзя** — заводите сессию так же, как
`builder-keyboard` (`tests/helpers/session.ts`): учётка создаётся подкомандой
`api seed-user <email> <password>` внутри контейнера api (`docker exec`, мимо HTTP —
ведро регистраций не тратится), а вход идёт настоящей ручкой `POST /auth/login` (своё
ведро, `loginBurst = 5`). Имя контейнера по умолчанию `trillix-prod-local-api-1`,
переопределяется переменной `E2E_API_CONTAINER`.

## Запуск (локально)

Нужен поднятый prod-local (тест ходит на `https://app.localhost` / `https://f.localhost`):

```
make prod-local            # из корня репо — поднять стек
cd e2e && npm ci
npx playwright install chromium   # один раз
npm test
```

Chromium сам резолвит `*.localhost` в 127.0.0.1; недоверенный локальный CA Caddy
обходится `ignoreHTTPSErrors` (TLS настоящий, просто не доверенный).

## Переопределение адресов

`E2E_APP_URL` и `E2E_RENDERER_URL` — на случай других хостов (по умолчанию
`https://app.localhost` и `https://f.localhost`).

## CI

Job поднимается отдельно (не на каждый PR — стек тяжёлый): `workflow_dispatch` +
nightly (шаг 7b фазы 7).
