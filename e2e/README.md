# E2e (Playwright) — сквозной smoke против prod-local

Гоняет **собранный** продукт в реальном браузере — ловит класс багов «прод-сборка ≠
dev» (пустая форма без entry-скрипта, форма без стилей, бикон, зарезанный CSP),
которые не видят ни Go-, ни vitest-тесты.

Девять сценариев, намеренно раздельных — у каждого свой предмет, и падение сразу
называет подсистему, а не «что-то в проде»:

- **`full-loop`** (ARCHITECTURE §8) — регистрация → сборка формы слэш-редактором и
  диалогом типов → публикация → ответ с мобильного вьюпорта → таблица → CSV.
  Ходит через билдер **мышью**; сюда же добавляются новые типы вопросов
  (шкала и согласие — фаза 8.5 шаг 2), потому что DoD требует от них полного цикла.
- **`builder-keyboard`** — сквозной критерий фазы 13: форма собирается **одной
  клавиатурой** (Enter из названия → «/» с фильтром → `Mod+Alt+→` в ряд → `Mod+Enter`
  к вариантам) → публикация → ответ респондента; ряд из двух вопросов проверяется на
  полотне, у респондента на десктопе и столбиком на телефоне. Форма создаётся через
  API: предмет сценария — полотно, а не кнопка «Новая форма».
- **`form-settings`** — свой текст благодарности и лимит мест (фаза 8.5 шаги 1 и 4):
  второй респондент упирается в «приём закрыт». Форма собирается через API.
- **`visits-funnel`** — визит биконом под прод-CSP, конверсия на карточке, воронка,
  `410` на закрытой форме (фаза 8.5 шаги 6 и 6б). Форма собирается через API.
- **`multipage`** — форма из трёх страниц (фаза 19): «Далее» не пускает с пустым
  обязательным ЭТОЙ страницы и молчит про следующие, хром виден только на первой,
  хода назад нет ни одного (экранной кнопки, клика по линии шага и записи в истории —
  системная «Назад» уводит со страницы), отправка приходит одним ответом со всех
  страниц, а ушедший со второй страницы стоит в воронке на ЕЁ первом вопросе.
  Форма собирается через API.
- **`embed`** — форма на постороннем сайте (фаза 20): блок вставленным сниппетом,
  авторесайз, **отправка ответа из фрейма**, виджет по кнопке с закрытием по Esc, и
  регресс на заголовки — кабинет остаётся `DENY`, а `/r/*` отдаётся без
  `X-Frame-Options` и с `frame-ancestors *`. Единственное место, где ослабление
  фрейминга проверяется вообще: **в dev CSP нет**. Страница-хозяин раздаётся через
  `page.route` на `https://embed-host.test` — для браузера это полноценный чужой
  origin, поэтому ни сервера, ни правок прод-конфига ради теста не нужно.
  **Хозяин по https и с выданным разрешением `local-network-access`** — цена того, что
  прод-контур живёт на loopback: Local Network Access в Chrome режет запрос со
  страницы-хозяина к `f.localhost` (по http — наглухо, по https — до разрешения), и
  режет молча: загрузчик не грузится, фрейма нет, падает первый же поиск поля внутри
  него. На проде ни того ни другого не нужно — `f.trillix.ru` обычный публичный адрес.
- **`workspace-team`** — командное пространство (фаза 16): приглашение коллеги, роли,
  отзыв доступа. Форма собирается через API.
- **`logic`** — условная логика (фаза 21): скрытый вопрос отсутствует в DOM, скрытый
  вариант не приходит в список и не попадает в ответ, перескок страницы доводит до
  кнопки отправки, знаменатель сводки — «вопрос показали». Форма собирается через API.
- **`design`** — оформление формы (фаза 22): тёмная тема и свои цвета стоят в теге
  `<html>` **в сыром ответе сервера**, то есть до единой строчки JS; preload шрифта
  указывает на файл, который реально собрал vite; бейдж «Сделано в Trillix» стоит на
  бесплатной форме и на экране «Спасибо»; публикация со своим CSS отвечает `402`, а
  черновик с ним же перед этим сохраняется `200`; форма без оформления отдаёт прежнюю
  оболочку; **свой CSS красит превью и не трогает кабинет вокруг** (TD-60 — граница
  здесь граница документов, и её не видит ни один юнит). Первый кадр проверяется
  **текстом ответа, а не DOM'ом**: в DOM к моменту проверки уже поработал клиент, и
  отличить его от сервера невозможно. Доставка авторского CSS **респонденту** сюда не
  входит — учётка сидируется на бесплатном тарифе, а выдать пространству платный план
  мимо БД e2e не умеет. Форма собирается через API; единственный заход в билдер — шаг
  про превью, и он про границу документов, а не про UI.

  **Проверка превью свёрнута в этот же тест, а не вынесена отдельным.** Каждый тест —
  это ещё один `POST /auth/login`, у входа своё ведро (`loginBurst = 5`), и
  двенадцатый вход в наборе роняет последний сценарий по алфавиту (`workspace-team`) —
  ровно тот же капкан, который в своё время выгнал регистрацию из всех сценариев,
  кроме `full-loop`. Лимит ради тестов не ослабляется (инвариант 6), значит новая
  проверка живёт там, где сессия уже есть.

Правило разделения: через билдер ходят только `full-loop` (мышью) и
`builder-keyboard` (клавиатурой). Остальные строят форму запросами к API — иначе
каждая правка редактора красила бы в красный тесты, которые про редактор ничего не
проверяют.

**Регистрация под rate-limit'ом — её тратит ровно один сценарий.** `registerBurst = 3`
при пополнении ~1 токен / 30 с (`cmd/api/main.go`), а лимит ради тестов не
ослабляется (инвариант 6). Пока через UI регистрировались все три старых сценария,
бурст выбирался в ноль, и **повторный прогон в течение ~1,5 минут падал на шаге
регистрации** — с виду «тест сломался», хотя сломался лимитер по IP; последний по
алфавиту `visits-funnel` ловил это регулярно.

Поэтому регистрация осталась только у `full-loop`, которому она **предмет** проверки.
Остальные заводят сессию через `tests/helpers/session.ts`: учётка создаётся
подкомандой `api seed-user <email> <password>` внутри контейнера api (`docker exec`,
мимо HTTP — ведро регистраций не тратится), вход — настоящей ручкой
`POST /auth/login` (своё ведро, `loginBurst = 5`). Имя контейнера по умолчанию
`trillix-prod-local-api-1`, переопределяется переменной `E2E_API_CONTAINER`. **Новый
сценарий регистрируется только если проверяет саму регистрацию.**

## Запуск (локально)

Нужен поднятый prod-local (тест ходит на `https://app.localhost` / `https://f.localhost`):

```
make prod-local            # из корня репо — поднять стек
cd e2e && npm ci
npx playwright install chromium   # один раз
npm test
```

Chromium сам резолвит `*.localhost` в 127.0.0.1; недоверенный локальный CA Caddy
обходится `ignoreHTTPSErrors` (TLS настоящий, просто не доверенный).

**Стек, поднятый давно, надо пересобрать.** `builder-keyboard` зовёт подкоманду
бинарника внутри контейнера (`api seed-user`), а `docker compose up -d` не
пересоздаёт контейнер, если образ с тем же тегом уже был, — стек может месяцами жить
на старом бинарнике. Симптом: сценарий падает первой же строкой с «бинарник без
подкоманды seed-user». Лечится `make prod-local` (он собирает образ заново). В CI
такого не бывает: job поднимает стек с нуля каждый прогон.

**Правка ТОЛЬКО фронта — тот же капкан с другого конца, и симптом злее.** Go-бинарник
не изменился → образ тот же → `up -d` контейнер `api` не пересоздаёт, а `index.html`
рендерера он держит в памяти с момента старта (шаблон для OG-меты). Свежая сборка
кладёт в том ассеты с НОВЫМИ хешами, api продолжает отдавать HTML со старыми, Caddy на
несуществующий `/assets/*` отвечает SPA-фоллбэком — и браузер получает `index.html`
вместо модуля: «Failed to load module script… MIME type text/html». Падают **все**
сценарии сразу, включая те, что фронта не касались. Лечится пересозданием api:

```
set -a && . ./.env.prod-local && set +a && \
  docker compose -p trillix-prod-local --env-file .env.prod-local \
    -f deploy/compose.prod.yml -f deploy/compose.local-media.yml up -d --force-recreate api
```

## Замер производительности полотна (`perf/`) — прибор, а не тест

`perf/` — оснастка пунктов **TD-32** (набор текста) и **TD-55** (перетаскивание): она
собирает формы на 13/61/199 блоков через API, набирает символы в подпись, жмёт `Enter`
и делает одно перетаскивание, снимая метрики CDP (`Performance`, `HeapProfiler`) и
счётчики самой страницы (мутации DOM, `ResizeObserver`, `getBoundingClientRect`, длины
кадров).

**В `npm test` она не входит** — свой конфиг (`playwright.perf.config.ts`), никаких
утверждений о поведении, минуты работы. Запускается руками:

```
make prod-local                                  # стек обязан быть свежим
cd e2e && PERF_LABEL=baseline npm run perf       # замер ДО
# ...правки кода, пересборка prod-local...
cd e2e && PERF_LABEL=after npm run perf          # замер ПОСЛЕ
node perf/compare.mjs baseline after
```

Результаты ложатся в `perf/results/<метка>.json` и **коммитятся**: критерий приёмки
пункта техдолга — «дефект воспроизведён до починки и не воспроизводится после, тем же
способом» (`PROCESS.md` §1.0), а замер только «после» одинаково выглядит и когда фикс
работает, и когда он не применился. Абсолютные числа привязаны к машине — сравнивать
можно лишь два прогона одной оснастки на одном железе.

Счётчик, чей патч не встал, отдаётся как `null` и печатается «н/д», а не нулём:
несработавшая диагностика обязана отличаться от честного нуля (`PROCESS.md` §4).

## Переопределение адресов

`E2E_APP_URL` и `E2E_RENDERER_URL` — на случай других хостов (по умолчанию
`https://app.localhost` и `https://f.localhost`).

## CI

Job поднимается отдельно (не на каждый PR — стек тяжёлый): `workflow_dispatch` +
nightly (шаг 7b фазы 7).
