## 1. Критерий приёмки

Цитата из [`POST-MVP.md`](../POST-MVP.md), «Демо в конце фазы»:

> Респондент прикладывает PDF с телефона → автор скачивает его из таблицы ответов →
> попытка загрузить .exe или файл сверх лимита отбивается до начала загрузки → удаление
> ответа удаляет и файл из бакета (проверено в консоли хранилища).

Детализация до наблюдаемых шагов (то, что реально проверяется руками):

1. На полотне по «/» вставляется блок «Файл»; в его настройках — сколько файлов, потолок
   размера, какие типы. Вид блока одинаков в редакторе, превью и у респондента.
2. Респондент бросает PDF в зону загрузки → полоса прогресса → карточка файла с именем и
   размером и крестиком «убрать». Отправка формы проходит.
3. В таблице ответов у колонки вопроса — имя файла ссылкой; клик скачивает **тот же**
   файл. Ссылка ведёт на наш эндпоинт, а не на подпись хранилища.
4. Попытка приложить `.exe` (и `.svg`) отбивается **до** начала загрузки, файл сверх
   потолка — тоже; ни один байт в бакет не уходит.
5. Удаление ответа в кабинете → объекта нет в консоли хранилища, строки
   `submission_files` нет в базе.
6. Загрузка, после которой форму так и не отправили, исчезает из бакета сама в течение
   суток.

Definition of Done фазы (оттуда же, дословно): байты файлов не проходят через Go-процесс;
осиротевшие объекты собираются (тест TTL-чистки); presigned-подписи не позволяют превысить
лимиты; в бэкап-процедуру добавлен пункт про бакет.

## 2. Что уже есть — на чём стоим

Задача не изобретает ничего из перечисленного заново.

| Механизм | Где | Что берём |
|---|---|---|
| `internal/blob` | фаза S3-медиа | sigv4 руками, `Put/Get/Delete`, сентинел `ErrNotFound`. **Нет** `Presign` и `HeadObject` — отложены до первого потребителя, им становится эта фаза |
| `internal/media` | там же | образец доменного хранилища: узкий интерфейс у потребителя, проверка доступа **до** работы с байтами, ошибки доменными сентинелами |
| токен формы | `internal/token` | HMAC-подпись времени выдачи, окно `[3с, 24ч]`. Тот же барьер ставится на выдачу слота загрузки |
| лимитер по IP | `httpserver.RateLimitByIP` | своё ведро на выдачу слотов, отдельное от приёма ответов (инвариант 6: в тестах — пермиссивная реализация) |
| `entitlements` | фаза 17 `DEV-PLAN` | каталог возможностей, `Kind`/`Scope`/`Meter`, тест «каждый план называет каждый ключ» |
| реестр типов блоков | `blocks/contract.ts`, `domain/schema.go` | `Record<BlockType,…>` без `Partial` и рукописный `blockTypes` + тест паритета: новый тип **не соберётся**, пока не заполнен целиком |

## 3. Конструкция: поток загрузки

Решение владельца 2026-08-17: **байты идут в хранилище напрямую**, как записано в DoD
фазы. Go выдаёт право на запись и проверяет результат, но байтов не видит.

```
1. респондент выбирает файл
2. рендерер → POST /public/v1/forms/{slug}/uploads
                { token, blockId, name, size, contentType }
3. API: лимитер по IP → подпись и возраст токена → форма опубликована и принимает
        ответы → блок существует и имеет тип file → тип и размер проходят настройки
        блока И жёсткий белый список → квота хранилища воркспейса
     → INSERT submission_files (состояние «ожидает»)
     → presigned PUT на 5 минут, ключ мнёт сервер
     ← { uploadId, url, headers }
4. браузер: XHR PUT прямо в S3 (прогресс — из события upload.onprogress)
5. отправка формы: answers[blockId] = ["<uploadId>", …]
6. приём ответа: для каждого uploadId — строка «ожидает» этой формы, не заявленная,
        не старше суток → HeadObject: объект есть, размер совпадает
     → claimed_at, submission_id
```

**`uploadId` — это и есть право на файл.** Случайный UUID, выданный сервером; знает его
только тот, кому выдали слот. Поэтому заявление не требует ни сессии, ни привязки к
заранее объявленному `submission_id` (рендерер генерирует его лениво, в момент отправки —
`FormView.tsx`), и подобрать чужую незаявленную загрузку нечем.

## 4. Модель данных

### 4.1. Тип блока `file`

Отвечаемый (`family: 'answer'`), собственного текста не несёт, ряд делить может.
Настройки — три новых ключа в общем мешке (`settings.ts`) с владением у типа:

| Ключ | Что | Потолок |
|---|---|---|
| `maxFiles` | сколько файлов принимает вопрос | 1..10, дефолт 1 |
| `maxFileSize` | потолок одного файла, МиБ | 1..25, дефолт 10 |
| `accept` | какие семейства типов автор пускает | подмножество нашего белого списка |

Автор выбирает **внутри** нашего белого списка, а не свободной строкой: `accept` из
пользовательского ввода означал бы, что разрешение на `.svg` выдаёт себе автор формы.

### 4.2. Формат ответа

`answers[blockId]` — **массив строк-`uploadId`**, как у `multi_choice` — массив id опций.
Ни имени, ни размера, ни MIME в ответе нет намеренно: всё это клиентские утверждения, и
хранить их рядом с ответом значило бы иметь два источника правды, из которых один —
недоверенный. Правда о файле живёт в `submission_files` и проверена `HeadObject`.

### 4.3. Таблица `submission_files`

```
id            uuid pk        -- он же uploadId, он же капабилити
workspace_id  uuid           -- денормализовано: квота и чистка считаются по нему
form_id       uuid
block_id      text           -- блок, для которого выдан слот
submission_id uuid null      -- NULL, пока ответ не пришёл
object_key    text unique
original_name text           -- вычищенное имя, данные, не путь
size_bytes    bigint         -- при выдаче — заявленный, при заявлении — проверенный
content_type  text
created_at    timestamptz
claimed_at    timestamptz null
```

Рассматривал вариант «ключ объекта прямо в JSONB ответа, сироты искать листингом
бакета» — отверг: без таблицы нет ни квоты (её нечем считать), ни сборки сирот (`Delete`
по листингу — это обход всего бакета), ни каскада при удалении ответа, а `ListObjects` в
`blob` пришлось бы писать всё равно.

### 4.4. Ключ объекта

```
answers/<workspace_id>/<form_id>/<uploadId>.<ext>
```

Ключ мнёт **сервер**, целиком. Имя, присланное клиентом, в ключ не попадает ни в каком
виде — иначе `../` и юникодные разделители стали бы нашей заботой. Расширение берётся из
белого списка по разрешённому MIME, а не из присланного имени.

## 5. Безопасность

Публичный эндпоинт, выдающий анониму право записи в наше хранилище, — самая опасная
поверхность продукта на сегодня. Разбор по угрозам; каждая строка проверяется тестом.

| Угроза | Ответ |
|---|---|
| **Бесплатное хранилище / DoS.** Любой шлёт файлы в любую опубликованную форму | валидный токен формы (подпись + окно возраста, как у приёма) → своё ведро лимитера по IP → потолок размера на файл → квота хранилища воркспейса, спрашиваемая **до** выдачи слота → TTL на незаявленные загрузки |
| **Stored XSS через SVG/HTML.** Классика загрузок | жёсткий **чёрный** список (`svg`, `html`, `xhtml`, `js`, `mjs`, `wasm`, `htm`) поверх белого; выдача только `Content-Disposition: attachment` и `Content-Type: application/octet-stream` через `response-*` в presigned GET; файлы **никогда** не отдаются с нашего домена — путь `/media` Caddy их не обслуживает |
| **Клиент выбирает ключ → перезапись чужого объекта** | ключ формирует сервер, подпись выписана ровно на него; клиент ключ не присылает вовсе |
| **IDOR на чтении.** В ответе указана чужая загрузка | скачивание — приватный эндпоинт с проверкой членства в воркспейсе (инвариант 1) → 302 на presigned GET на 60 секунд. Прямой доступ к бакету закрыт: бакет **приватный**, в отличие от медийного |
| **Обход потолка размера** | `Content-Length` входит в подпись; сверх того при заявлении `HeadObject` сверяет реальный размер с заявленным — разошлись, объект удаляется, ответ 422 |
| **Инъекция в заголовок через имя файла** | имя чистится от управляющих символов, `"` и разделителей пути, режется по рунам; в `Content-Disposition` уезжает по RFC 5987 |
| **Утечка presigned-URL** | это учётные данные: TTL 5 мин на PUT, 60 с на GET; в логи не пишутся; **в CSV не уезжают** — там имя файла и ссылка на наш эндпоинт, иначе выгрузка протухала бы через минуту после скачивания |
| **Вредонос** | антивируса в v1 **нет**, и это сказано вслух автору и здесь. Снижает риск то, что файл у нас не исполняется и не открывается инлайн, а отдаётся вложением. Скан — отдельная задача при появлении спроса |
| **Декомпрессионные бомбы** | файлы ответов **не обрабатываются вообще**: ни декодирования картинок, ни распаковки — в отличие от `internal/media`. Правило записывается в `S3.md`: первый, кто захочет «превью картинки в таблице ответов», откроет декодер для чужих байтов |
| **152-ФЗ** | к нам поедут паспорта и справки: приватный бакет в РФ, удаление вместе с ответом, бакет в бэкап-процедуре |

## 6. Квота и тариф

Новый ключ каталога `storage_per_workspace` (`Quota`, `WorkspaceScope`, новый
`StorageMeter` — сумма `size_bytes` заявленных строк воркспейса). Решение владельца
2026-08-17: ключ заводится **сейчас**, у всех планов `null` = безлимит, как у остальных
тарифов сегодня; включается одним `UPDATE` (`BILLING.md` §6). Без него у анонимной
загрузки нет верхней границы расхода вообще, а добавление ключа позже потребовало бы
пересчёта уже загруженного.

Сверхлимитный ответ на выдаче слота — 402 со списком мешающего, как у публикации.

## 7. Жизненный цикл

- **Сирота** (слот выдан, ответ не пришёл) — строка «ожидает» старше суток: периодическая
  задача в `internal/periodic` удаляет объект и строку. Сутки — потолок возраста токена
  формы: дольше жить незаявленной загрузке незачем.
- **Удаление ответа** — объекты его файлов удаляются в той же операции.
- **Удаление формы и пространства** — то же, каскадом.
- **Удаление аккаунта** — сегодня это пометка `users.deleted_at` без чистки данных
  (фаза 23), файлы остаются вместе с ответами. Реальная чистка — фаза 12 `POST-MVP`
  (152-ФЗ), и файлы ответов входят в её объём.

## 8. Инфраструктура

- **Второй бакет**, приватный (`S3_FILES_BUCKET`): политики несовместимы с медийным —
  тот public-read.
- **CSP**: `connect-src 'self'` на домене рендерера запрещает PUT в хранилище. В
  `deploy/caddy/Caddyfile` добавляется origin хранилища в `connect-src` **только** на
  домене форм; на домене кабинета остаётся как было.
- **CORS на бакете**: `PUT` с origin домена форм. Настраивается у провайдера руками —
  шаг для владельца, проверить нечем, кроме живого прода.
- **Бэкап**: пункт про бакет файлов в `deploy/backup.sh` и `RESTORE.md` (DoD фазы).

## 9. Границы: чего в v1 нет

Возобновляемые и многочастные загрузки (файлы до 25 МиБ грузятся одним PUT); превью
картинок в таблице ответов (см. §5, декодер); антивирус; общий потолок на ответ сверх
`maxFiles × maxFileSize`; файлы в сводке ответов (блок ведёт себя как текстовые типы — не
агрегируется); файлы в подстановке «@» (имя файла — не ответ, который имеет смысл
подставлять в текст).
