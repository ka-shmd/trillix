> сейчас». ADR-строки (раздел 11) утверждены и внесены в §10
> [`ARCHITECTURE.md`](../ARCHITECTURE.md).
>
> **Как оно работает и как расширять — [`S3.md`](../S3.md)** (живой, скилл `s3-media`).
> **При любом расхождении побеждает он**, а выше обоих — `ARCHITECTURE.md`.
>
> Известные гэпы подсистемы — TD-16 (осиротевшие объекты не собираются) и §5
> [`TECH-DEBT.md`](../TECH-DEBT.md).

**Контекст.** ARCHITECTURE.md §1 относит файловые аплоады к «не входит в MVP, но архитектура должна допускать». Эта работа вводит **первую подсистему хранения бинарников в продуктовом контуре** и первого её потребителя — лейаут-блок «картинка». Суть задачи не «сделать картинку», а **заложить слой работы с S3 так, чтобы будущие потребители втыкались без переделки**; картинка — первый вертикальный срез, проверяющий фундамент end-to-end.

---

## 1. Область и не-цели

**Входит:**
- Агностичный S3-клиент (слой-1), пригодный для всех будущих потребителей.
- Доменное хранилище картинок (слой-2, public-read) + приём загрузки автором.
- Тип блока `image` (контентный, не отвечаемый) во всех трёх поверхностях формы.
- Инфра MinIO для dev/prod-local; конфиг; раздача через Caddy.

**Не входит (осознанно отложено):**
- Файлы в ответах респондентов — **POST-MVP Фаза 17** (private-бакет, presigned-PUT мимо Go, `attachment`, TTL-сироты). Переиспользует слой-1, добавляет свой слой-2.
- Бэкапы — **Фаза 10** (cron, шифрование `age`, *другой* провайдер). Почти ортогональны: пишет не API, а cron-скрипт; Go-абстракцию под них не проектируем (см. §3).
- Своя og:image на форму (сейчас `OGImageURL` — общая заглушка). Становится возможной после этого слоя, но это отдельная задача.
- WebP/GIF, ресайз-варианты, CDN, per-workspace квоты хранилища, GC сирот с refcount.
- Async-инфра: transactional outbox (ТГ/почта/вебхуки) и джоб-воркер пост-обработки медиа — отдельные будущие задачи. Аплоад синхронный, к outbox не привязан (обоснование — §6a).

## 2. Зафиксированные решения

| Решение | Альтернатива | Почему так |
|---|---|---|
| S3-совместимое хранилище сейчас | Локальный диск | Владелец выбрал S3 как фундамент под будущее (файлы ответов, экспорты). Локальный диск потребовал бы переписать при первом же S3-потребителе |
| MinIO в dev/prod-local, арендованное S3 в проде | Разный код по контурам | S3 — стандартный протокол; и MinIO, и арендованное S3 говорят одинаково. Различие контуров — только в env (endpoint/creds/bucket), кода не меняется |
| Ручной sigv4 (stdlib) | minio-go / AWS SDK | Нужны только Put/Delete (чтение public — голый URL без подписи). Крохотная поверхность подписи не оправдывает зависимость сверх замороженного списка (internal/CLAUDE.md) |
| Слой-1 агностичный клиент + слой-2 доменные хранилища | Единый `BlobStore.Upload()` на всех | Public-картинки и private-файлы противоречат по ACL/presign/disposition; god-интерфейс сломается на фазе 17 `POST-MVP` |
| Узкий интерфейс объявляет потребитель | Общий интерфейс в пакете-клиенте | Конвенция проекта (интерфейсы на стороне потребителя); нет преждевременной абстракции, всё мокается |
| Public-read, раздача через Caddy reverse-proxy `/media/*` | Прямой URL бакета в CSP / presigned-GET | Картинки форм публичны по природе. Caddy-proxy даёт same-origin (`img-src 'self'`), прячет endpoint бакета, байты через Caddy (не Go). Presigned ломает кэш и og:image |
| Отдельные бакеты по видимости (`app-media` public, `app-uploads` private) | Один бакет + prefix-политики | ACL уровня бакета проще и надёжнее; ошибка в prefix-политике легко делает приватное публичным |
| В схеме блока — ключ объекта, не URL | Полный URL в JSONB | URL в данных = миграционный ад при смене провайдера. Ключ + `MEDIA_BASE_URL` → переносимость (тот же инвариант «dev/prod только env») |
| PNG/JPEG, ре-энкод + чистка EXIF + гард размеров | Пропуск как есть / WebP-GIF | stdlib полноценно декодит/жмёт PNG/JPEG без зависимостей; ре-энкод сносит EXIF/GPS (приватность) и decompression-bomb. WebP-энкодера в stdlib нет |

## 3. Таксономия объектов S3 (почему нельзя один store)

Разные объекты несовместимы по политикам — это определяет двухслойность:

| Объект | Кто пишет | Видимость | Отдача | Жизненный цикл | Провайдер |
|---|---|---|---|---|---|
| Картинки блоков (сейчас) | API (автор) | public-read | прямой URL, кэш | привязан к форме | основной |
| Файлы ответов (фаза 17 `POST-MVP`) | браузер (presigned-PUT, байты мимо Go) | private | presigned-GET + `attachment` | TTL-чистка сирот | основной |
| Бэкапы (фаза 10 `POST-MVP`) | cron, не API | private, шифр. `age` | восстановление вручную | ротация 14+8 | **другой** |
| Экспорты CSV | API | — | стримятся, в S3 не кладём | — | — |

Выводы:
1. **«Байты через Go» — свойство потребителя, не глобальное правило.** Картинки — через Go (малы, нужна валидация/ре-энкод); файлы ответов — presigned мимо Go.
2. **Бэкапы ортогональны.** Пишет cron (возможно `rclone`/`mc` вне Go-бинаря), другой провайдер, свои креды. Дизайн слоя-1 под них не подгоняем — лишь оставляем пригодным к переиспользованию, если позже выберем Go.

## 4. Архитектура слоёв

**Слой-1 — транспорт: `internal/blob`.** Провайдеро-агностичный S3-клиент. Конкретный `*Client`, параметризован endpoint/region/creds + path-style. Реализовано (шаг 1): `PutObject`, `GetObject`, `DeleteObject`, `CreateBucket`. Отложено до появления потребителя (YAGNI): `PresignGet/Put` (фаза 17 `POST-MVP`), `HeadObject` (дедуп в MediaStore), `ListObjects` (GC сирот). Знает S3 HTTP + sigv4; не знает слов «картинка»/«форма». Один на всё приложение. Оба стиля адресации (path-style/virtual-hosted) есть; тестом покрыт path-style против MinIO.

**Слой-2 — доменное хранилище: `MediaStore`.** Тонкая обёртка над слоем-1: владеет политикой (`bucket=app-media`, ключ = `<workspace_id>/<sha256><ext>`, Content-Type картинок). Живёт в модуле-потребителе (media/forms).

**Интерфейс — у потребителя.** Слой-1 отдаёт конкретный клиент; сервис объявляет узкий интерфейс, который ему нужен:

```go
// в пакете сервиса
type blobPutter interface {
    PutObject(ctx context.Context, bucket, key string, r io.Reader, contentType string) error
}
```

Фаза 17 `POST-MVP` объявит свой (`presigner`) — общий интерфейс не пухнет.

**Тестирование слоя-1** — интеграционный тест против MinIO в testcontainer (паттерн `internal/pgtest`), тег `integration`. Единственный способ держать sigv4 честным; без него баг подписи виден только в prod-local.

## 5. Модель данных (контракт схемы)

Ложится на каркас 8-го типа `text`. Зеркалим Zod ↔ Go одним PR, тесты обеих сторон.

- `BlockSettings` (`formSchema.ts` + `schema.go`): добавить

## 6. Приём и обработка картинки

Эндпоинт `POST /api/workspaces/{ws}/media` (или `/api/forms/{id}/media`) — за `RequireAuth` + проверка членства в воркспейсе + rate limit. `MaxBytesReader` на теле.

Поток:
1. Принять multipart (одно поле-файл).
2. **Сниффинг типа по контенту** (`http.DetectContentType`), не по заголовку. Whitelist: `image/png`, `image/jpeg`.
3. **Гард размеров** через `image.DecodeConfig` (ширина×высота до полного декода) — защита от decompression-bomb. Лимит пикселей.
4. **Полный декод → ре-энкод** (image/png, image/jpeg) — сносит EXIF/GPS-метаданные и нормализует байты.
5. `key = <workspace_id>/<sha256(ре-энкод-байтов)><ext>` — контент-адресация: идемпотентный PUT, дедуп.
6. `MediaStore.Put` → `PutObject(app-media, key, bytes, contentType)` с `X-Content-Type-Options` на отдаче.
7. Ответ: `{ imageKey }`. Билдер кладёт его в `settings.imageKey` блока (автосейв схемы).

Ошибки → `ErrValidation` (422) через `respond.go`, никаких `http.Error` в handler.

## 6a. Синхронность, почему не outbox, и прогресс загрузки

**Аплоад картинки — синхронный HTTP-запрос, не async через outbox.** Transactional outbox (ARCHITECTURE §9, метится на вебхуки) решает: атомарно с коммитом БД зафиксировать намерение внешнего best-effort side-effect, который идемпотентно повторяем и терпит задержку. Загрузка картинки не подходит ни по одному признаку:
- Синхронна по сути — смысл в том, чтобы автор сразу увидел картинку в билдере.
- Пейлоад — сами байты; класть мегабайты в Postgres-строку outbox, чтобы воркер переложил в S3, — раздувание БД/WAL/бэкапов (blob-в-БД антипаттерн).
- Нет транзакции, с которой надо быть атомарным (блок с ключом сохраняется отдельным автосейвом схемы — клиентская 2-шаговая оркестрация).
- Ретраи — работа клиента (кликнуть ещё раз), не фонового воркера (иначе плодит сирот).

Поток: `browser → POST multipart → Go валидирует+ре-энкод+PUT в S3 синхронно → возвращает {imageKey}`. **Ответ HTTP и есть сигнал завершения — статус-эндпоинт не нужен.**

**Outbox — отдельная будущая задача под уведомления, не под аплоад.** Он правильный паттерн для ТГ/почты/вебхуков на событие (новый ответ): доставка независима от коммита, ретраи с бэкоффом, at-least-once + идемпотентность. Но это POST-MVP; строить сейчас под фичи, которых не делаем, — спекулятивная общность (YAGNI). Аплоад к нему **не привязываем**. Когда outbox появится, S3-слой из этой задачи — его независимый сосед.

**Где async легитимно вернётся для медиа — пост-обработка** (превью/ресайз-варианты, скан): там уместен джоб-воркер + модель статуса (`202 Accepted` + ресурс `processing`, поллинг/подписка). В v1 нет (варианты отложены) → статус-машины нет. Будущий шов: джоб-воркер — сосед outbox-воркера, не сам outbox. Presigned-direct (мимо Go) — путь фазы 17 `POST-MVP` для больших файлов ответов; для картинок не годится (нельзя снять EXIF/ре-энкодить), поэтому картинки идут через Go.

**Прогресс/% — клиентская история, бэкенд его не репортит:**
- % аплоада (browser→Go) — из `XMLHttpRequest.upload.onprogress` (`loaded/total`); `fetch()` прогресс тела надёжно не даёт, для бара — XHR.
- Плечо Go→S3 клиенту не видно; для картинок автора (единицы МБ) оно + ре-энкод — доли секунды, показываем индетерминантное «обработка…».
- Статус-поллинг не нужен: жизненный цикл запроса `in-flight → 200+key → 4xx/5xx` ложится на обязательные состояния билдера loading/error/success.
- UX-мгновенность: локальный превью `URL.createObjectURL(file)` сразу → XHR с прогресс-баром → на 200 подмена blob-URL реальным `imageKey` + автосейв → на ошибке «повторить». Без единого async-механизма на бэке.

## 7. Хранилище: бакеты, ключи, подпись

- **Бакеты по видимости:** `app-media` (public-read сейчас), `app-uploads` (private, фаза 17 `POST-MVP`). ACL уровня бакета.
- **Публичность без листинга:** политика `app-media` разрешает анонимный `GetObject`, запрещает `ListBucket`. Ключ-хэш неугадываем (как Notion/Tally); черновиковые картинки технически публичны — принято осознанно (инвариант 5 формально не нарушается: блоб не раскрывает существование формы).
- **Ключи:** `<workspace_id>/<sha256><ext>` — неймспейс под будущие per-tenant политики/квоты, внутри — контент-хэш.
- **sigv4:** только на `Put`/`Delete` (чтение — публичный URL). Тело в памяти → `sha256` payload, без chunked-signing. Учесть: кодирование пути (слэши не эскейпить), `region` в подписи (MinIO дефолт `us-east-1`), clock skew.
- **path-style** (`endpoint/bucket/key`) — флагом конфига (MinIO и часть РФ-провайдеров требуют path-style; AWS — hostname-style).
- **Дедуп ↔ удаление — ловушка:** контент-хэш → две формы могут ссылаться на один объект. В v1 **не удаляем** объект при удалении блока (иначе снесём чужую картинку). GC с refcount — позже.

## 8. Раздача (реализовано, шаг 4)

- **Caddy reverse-proxy `/media/*` → бакет `app-media`** на обоих доменах (`app.localhost` и `f.localhost`, сниппет `(media)` в `deploy/caddy/Caddyfile`): `handle_path` срезает `/media`, `rewrite` добавляет префикс бакета (`{$S3_MEDIA_BUCKET}`), upstream — `minio:9000`. Браузер видит **same-origin** → `img-src 'self'` покрывает и билдер, и рендерер; байты идут через Caddy, не Go. Иммутабельный кэш (`Cache-Control immutable`) — ключи контент-адресны.
- **URL — относительный `/media/<imageKey>`**, одинаковый на обоих origin (решение: не env-переменная, а относительный префикс; браузер резолвит против текущего origin). Ключ в данных, URL — вычисляемый (`'/media/' + imageKey`). Абсолютная база/CDN на реальном проде — будущая замена (тогда origin добавляется в CSP; для og:image формы, которая пост-MVP, понадобится абсолютный URL).
- **CSP:** `img-src 'self' data: blob:` — `'self'` покрывает раздачу same-origin, `blob:` — оптимистичный локальный превью билдера (`URL.createObjectURL`, шаг 5). В dev CSP нет.
- **dev без Caddy:** `/media/*` в dev проксирует **vite** на MinIO (`web/{app,renderer}/vite.config.ts`, rewrite → `/app-media/*`).

## 9. Безопасность (инварианты)

- Загрузка за `RequireAuth` + членство в воркспейсе + rate limit; `MaxBytesReader`.
- Whitelist по сниффингу контента; **SVG исключён** (носит скрипт); ре-энкод сносит EXIF/GPS и нормализует байты.
- Отдача с корректным `Content-Type` (проставлен на PUT) + `X-Content-Type-Options: nosniff`; листинг бакета выключен.
- `S3_SECRET_KEY` — секрет: в конфиг, не логируется (инвариант 7). Бэкапы (другой провайдер) — отдельные креды, не переиспользовать.
- `dangerouslySetInnerHTML` остаётся запрещён; `alt` рендерится как атрибут (автоэкранирование React).
- Публичный путь `/media` не раскрывает приватного больше, чем блоб по неугадываемому ключу.

## 10. Конфиг и инфраструктура

**Env (по конвенции internal/CLAUDE.md — одним коммитом в `config.Config` + `.env.example` + `.env.dev` + `.env.prod-local`):**
- `S3_ENDPOINT` — endpoint (dev/prod-local: MinIO-контейнер; прод: арендованное S3).
- `S3_REGION` — регион подписи (MinIO: `us-east-1`).
- `S3_ACCESS_KEY` — ключ доступа.
- `S3_SECRET_KEY` — **секрет**, не логируется.
- `S3_MEDIA_BUCKET` — бакет картинок (`app-media`).
- `S3_PATH_STYLE` — bool, path-style адресация.
- `MEDIA_BASE_URL` — база публичного URL картинок (без завершающего слеша).

Без ветвления по имени окружения — только смысловые флаги.

**Инфра:**
- MinIO-контейнер в `deploy/compose.prod.yml` (+ dev-подъём через `make dev`).
- init-контейнер `mc` (MinIO client): создать бакеты `app-media`/`app-uploads`, выставить public-read policy на `app-media`, запретить листинг.
- `make prod-local` остаётся честной репетицией: реальный S3-путь прогоняется локально против MinIO.
- 152-ФЗ (Фаза 9+): реальный прод-бакет — у РФ-провайдера; локально MinIO, разница только env.

**Не привязывать liveness API к S3:** S3 недоступен → падают только загрузки (автор видит ошибку); рендер существующих форм жив (картинки тянет браузер из Caddy/бакета, HTML/OG не зависят). API на старте из-за недоступного S3 не падает.

## 13. Подводные камни (сводка) и что отложено

**Учтено в дизайне:** sigv4 (узко, тест против MinIO), path-style/region конфигом, decompression-bomb (DecodeConfig-гард), EXIF/GPS (ре-энкод), дедуп↔удаление (не удаляем в v1), листинг бакета выключен, ключ-не-URL, CSP через Caddy-proxy, секреты не логируются, liveness не привязан к S3.

**Осознанно отложено — вынесено в реестр техдолга `docs/TECH-DEBT.md`:**
- **TD-16** — сироты и GC с refcount (объекты в бакете не удаляются, неограниченный рост).
- ~~**TD-17** — раздача `/media` на реальном проде~~ — закрыт (upstream раздачи из env `MEDIA_UPSTREAM`/`MEDIA_UPSTREAM_HOST`, см. `S3.md` §7).
- **§5 «Заметки на рост»** — публичность черновиковых картинок (осознанно), форматы-минимум (PNG/JPEG, без WebP/GIF/ресайза/CDN/квот), своя og:image на форму (пост-MVP), нереализованные `blob.Presign`/`Head`/`List` (до потребителя).
