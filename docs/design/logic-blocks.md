> **Статус: согласована владельцем 2026-08-16, влита в `main` ([#119](https://github.com/ka-shmd/trillix/pull/119)).**
> Написана до кода (`PROCESS.md` §1.0): задача вне плана, критерий приёмки — §11. Строки
> ADR §8 внесены в `ARCHITECTURE.md`.
>
> **Три места, где итог разошёлся с первой редакцией, помечены по тексту:** позиция блока
> (§3.1), варианты как цели того же действия (§3.5) и снос правил вместо переноса (§7).
> Здесь текст правился по ходу работы, а не оставлен историей, — спека ещё не архивная.
>

> инертность и вычислитель, остаётся в силе и здесь не переписывается.

## 1. Что решается

Сегодня условие — невидимое свойство вопроса. Автор видит на полотне значок, открывает
попап, читает правило одной строкой, правит его в диалоге. Ветвление формы нельзя
**прочитать**: чтобы понять, что происходит между вопросом 3 и вопросом 7, надо открыть
семь попапов.

Задача: правило становится **строкой полотна**, которую видно при чтении формы сверху вниз.
Образец — Tally: блок «When … Then …» стоит между вопросами, таскается и удаляется как
любой другой блок, респонденту не показывается.

### 1.1 Решения владельца (2026-08-16)

1. **Модель — настоящий блок схемы, цель по ссылке.** Тип `logic` с условием и списком
   действий; действие называет цель. Не «вид поверх прежней модели» и не позиционная
   императивная семантика Tally (варианты B и C, §2.3).
2. **Набор действий — как в Tally:** переход на страницу, обязательность, показать блоки,
   скрыть блоки, скрыть кнопку отправки. **Правка 2026-08-16:** отдельного действия для
   вариантов НЕТ — вариант выбора это такая же цель в дереве, что и вопрос, и целей у
   действия список. Первая редакция заводила `show_options`/`hide_options`; они удалены.
3. **`Calculate` в эту работу не входит** — отдельной задачей потом. Вычисления и баллы это
   не условие, а переменные формы: своя арифметика в двух языках, своё место показа
   результата, свои решения про хранение в ответе и CSV ([`logic.md`](logic.md) §2.1).
4. **Старые входы убираются полностью:** пункты попапа блока, пункт попапа варианта,
   «Переходы» на разрыве страницы, оба значка правил на строке. Вход в логику один — блок.

## 2. Модель данных

### 2.1 Новый тип блока

```
'logic' — семья 'content', carriesText: false, canShareRow: false, requiresCaption: false
```

Поле верхнего уровня блока, как `jumpIf` сегодня (свойство блока, а не типа — тот же довод,
что у `name` и `visibleIf`):

```ts
logic?: {
  when: LogicCondition      // ровно то дерево, что есть сегодня
  then: LogicAction[]       // до MAX_LOGIC_ACTIONS действий
}

type LogicAction =
  | { kind: 'show' | 'hide';        target: string }               // блок (голова группы)
  | { kind: 'require';              target: string }               // отвечаемый блок
  | { kind: 'show_options' | 'hide_options'; target: string; options: string[] }
  | { kind: 'jump'; to: string } | { kind: 'jump'; end: true }     // как jumpRuleSchema
  | { kind: 'block_submit' }                                       // «скрыть кнопку»
```

`when` и `then` необязательны по отдельности: блок, у которого ещё не выбрано условие или
не выбрано действие, — законное состояние черновика, как лист с пустым `value` сегодня.
Полупустой блок **инертен целиком** (§3.4).

### 2.2 Что из схемы УХОДИТ

`visibleIf` у блока, `requiredIf` у блока, `visibleIf` у варианта, `jumpIf` у разрыва
страницы — удаляются из Zod и из Go. Двух источников правды не заводим: пока поле-носитель
живо, оно рано или поздно разойдётся с блоком, и разойдётся молча.

Остаётся `required` (тумблер «Обязательный») — он не про логику.

### 2.3 Отвергнутые варианты модели

| Вариант | Почему нет |
|---|---|
| **B. Только вид:** строка у носителя, поля на месте | Строка не блок: не таскается, «+» и корзина значат не то, что у соседей. На полотне, где всё остальное — текст с одинаковыми правилами, это читается как поломка |
| **C. Полная семантика Tally:** действия применяются в порядке документа поверх состояния | Вычислитель переписывается с нуля в двух языках; инвариант `plan(schema, normalize(a)) == plan(schema, a)`, на котором стоит знаменатель сводки, доказывается заново. Цена несоразмерна выигрышу: у declarative-компиляции (§3) тот же наблюдаемый результат |
| Отдельная сущность «правила формы» рядом с блоками | Это и есть сегодняшнее «отдельное меню», только в схеме. Прочитать форму сверху вниз по-прежнему нельзя |

### 2.4 `schemaVersion` не двигается

Она **заморожена на единице до релиза** (решение владельца 2026-08-10): формат меняется в
лоб, документы в БД чинятся одноразовой правкой в том же PR, апгрейдеров на чтении нет.
Поэтому переезд правил — не цепочка версий, а одна конверсия (§7).

> **Долг, найденный попутно.** ADR §10 (строка «Условная логика не поднимает
> `schemaVersion`») и `EDITOR.md` пишут «остаётся 4» — формулировка дозаморозочная,
> реальность единица. Правится в том же PR, что и остальные строки §10.

## 3. Семантика

### 3.1 Инертность меряется У ЦЕЛИ, а не у блока

> **Правка 2026-08-16.** Первая редакция требовала «источники выше блока, цели ниже блока»
> ради читаемости. Владелец отменил её по образцу Tally, где цель выбирается из всего
> документа. Ниже — действующая формулировка.

Однопроходному обходу нужно ровно одно: **источник обязан быть решён к моменту, когда
решается ЦЕЛЬ**. Значит и мерить инертность надо у цели:

- лист инертен, если источник стоит **не выше цели** этого действия;
- позиция самого блока к этому отношения не имеет — он волен стоять где угодно, в том
  числе ниже того, что прячет.

Позиция блока значима ровно для двух действий, у которых цель — не блок, а страница:
**переход** и **«скрыть кнопку»** принадлежат той странице, на которой блок стоит, и их
условие считается от его позиции.

Вычислитель от этого не усложнился, а упростился: поле `guard` у правила исчезло.

Плата названа вслух: правило может стоять сколь угодно далеко от того, на что влияет, а
значков на строках вопросов нет (§5.4). Если читаемость формы от этого пострадает, вопрос
про пометки поднимется снова.

### 3.2 Показ и скрытие: две корзины, порядок блоков не влияет

Для цели G собираются два множества **действующих** (не инертных) условий: `shows` — из
действий «Показать», `hides` — из «Скрыть». Тогда

```
visible(G) = (shows пусто ИЛИ хотя бы одно из shows истинно)
             И НЕ (хотя бы одно из hides истинно)
```

Свойства, ради которых формула такая: результат не зависит от порядка блоков `logic` между
собой (иначе перетаскивание правила меняло бы смысл формы); «показать» переворачивает
умолчание цели в «скрыт», как в Tally; инертное действие выпадает из своего множества —
то есть равно отсутствующему, главная фраза фазы 21.

**Уровней два (правка 2026-08-16).** Голова группы адресует вопрос ЦЕЛИКОМ — подпись,
поле, контент внутри группы; любая другая строка группы адресует себя одну. Уровни
перемножаются: спрятанный вопрос не показывает своих строк. Первая редакция знала только
первый уровень, и «спрятать подпись, оставив поле» было невыразимо.

### 3.3 Обязательность складывается по ИЛИ

`required(B) = B.required === true ИЛИ хотя бы одно действующее действие «Обязателен» на B`.

**Это отменяет взаимоисключение `required`/`requiredIf`** (ADR §10). Оно держалось ровно на
том, что оба поля лежали на одном блоке и проверка была внутриблочной; теперь флаг у цели, а
действие — в другом блоке, и запрет стал бы кросс-блочным, то есть 422 в автосейве. Довод
«в UI пришлось бы объяснять дважды» остаётся в силе, поэтому конфликт ловится
**предупреждением в блоке** — «вопрос обязателен всегда, условие ничего не меняет».

Скрытый вопрос не обязателен никогда: видимость старше обязательности (без изменений).

### 3.4 Переход и блокировка отправки

- **Переход** принадлежит **странице, на которой стоит блок**, и срабатывает при уходе с
  неё. Порядок разрешения прежний: первое сработавшее правило сверху вниз по документу,
  цель только вперёд, назад и в никуда — инертно. Носитель меняется с `page_break` на
  `logic`; всё остальное в `nextPage` остаётся.
- **«Скрыть кнопку»** завершает обход на своей странице: кнопки «Далее»/«Отправить» нет,
  страниц дальше нет, план помечается `blocked`. Блоки следующих страниц не видны, значит
  ответы на них отбрасываются нормализацией без единой новой строки — механика уже есть.

**Сервер отвечает 422 на попытку отправить заблокированную форму.** Иначе «скрыть кнопку»
декоративно: `curl` проходит мимо неё. Инвариант 3 (валидация на бэке независимо от фронта)
требует ровно этого.

### 3.5 Варианты — цели того же действия

Отдельного действия для вариантов нет: `show`/`hide` принимают СПИСОК целей, и в нём
вперемишку id блоков и id вариантов. Кто чем оказался, разбирает компиляция по документу
(id блока старше id варианта при совпадении); дальше работают те же две корзины, что у
блоков (§3.2), только карта своя.

Вариант нельзя сделать обязательным — ссылка на него в `require` инертна, и об этом
предупреждает блок.

### 3.6 Полупустой блок

Нет условия, нет ни одного действия, все действия инертны — блок не делает ничего и не
мешает: форма ведёт себя так, будто его нет. Это то же правило «инертное равно
отсутствующему», просто на уровень выше листа.

## 4. Что вычислитель получает и что теряет

`planForm` / `PlanForm` перестают читать четыре поля носителей и получают **шаг компиляции**
перед обходом: пройти блоки, собрать из `logic`-блоков карты `shows`/`hides`/`requires`/
`optionRules` и список переходов по страницам. Дальше — сегодняшний обход, слово в слово:
позиции, `decided`, пустой ответ у скрытого источника, страницы, `stripHiddenAnswers`.

`FormPlan` прирастает одним полем: `blocked: boolean`.

Дублирование Go ↔ TS сохраняется как есть (ADR §10 в силе): одинаковые таблицы кейсов с двух
сторон, паритет операторов машинный. К нему добавляется **паритет действий** — тем же
тестом, что читает TypeScript.

## 5. Полотно

### 5.1 Строка блока

Поверхность `'object'` (фокусируемая строка с кольцом, своего текста нет) — как шкала и
дата. Внутри — контрол в два яруса:

```
Когда  [вопрос ▾] [оператор ▾] [значение ▾]                    ⋮
Тогда  [действие ▾] [цель ▾]                                   ⋮
```

Строки условий добавляются кнопкой, между ними переключатель И/ИЛИ. **Вложенные группы
инлайн не правятся** — «⋮» открывает существующий `ConditionEditor` в диалоге, где группы
уже есть. Инлайн-редактор для плоского списка, диалог для дерева: плоский случай — почти
все правила, дерево в строке полотна не помещается, а второй редактор дерева писать незачем.

Значения по-прежнему выбираются селектами по типу источника, а не свободным вводом (строгий
валидатор, `fields/README.md`).

### 5.2 Как ведёт себя в модели полотна

- **Всегда одиночка:** в группу вопроса не входит, `canShareRow: false` — правило в половине
  ряда не значит ничего (тот же довод, что у разрыва страницы).
- **Вставка** — раздел «Лэйаут» slash-меню и «+» на строке.
- **Драг и клавиатура** — общие правила блочного слоя, без исключений.
- **Респонденту не показывается:** `BlockField` возвращает `null`, как на `page_break`.

### 5.3 Предупреждения

В блоке, текстом под ярусом: источник удалён · источник ниже блока · цель выше блока ·
цель удалена · сравнение не подходит типу · значение не выбрано · цель обязательна всегда.
Считаются существующим `ruleWarnings`, расширенным на цели.

### 5.4 Что удаляется

`BlockActionMenu`: пункты «Показывать: …» и «Обязателен, если: …» (тумблер «Обязательный»
остаётся). Попап варианта: «Показывать: …». Строка разрыва: «Переходы: …». `BlockRow`: оба
значка правил (`GitBranch`, `SquareAsterisk`) и `BlockRuleDialog` вместе с монтированием по
клику. `JumpDialog` — целиком.

> **Риск, принятый владельцем.** Вопрос, спрятанный правилом из блока в полусотне строк
> выше, никак не помечен на своей строке. Значков не будет — это решение 2026-08-16
> («вход только через блок»). Если при работе окажется, что форма читается хуже, чем до
> переезда, вопрос поднимается снова, а не решается по ходу.

## 6. Три поверхности

| Поверхность | Что делает |
|---|---|
| полотно | показывает всё, включая блоки `logic`; правила видны и правятся на месте |
| превью | ведёт себя как рендерер: блоки `logic` не рисует, ветку показывает от ответов |
| рендерер | `logic` не рисует; скрытые вопросы и варианты не приходят; путь считается переходами; на заблокированной странице нет кнопки |

Бюджет рендерера (45 КиБ gzip) замеряется в слайсах 2 и 4: компиляция едет к респонденту,
зато четыре чтения полей уходят.

## 7. Что делать с существующими документами

**Правила не конвертируются, а сносятся** (решение владельца 2026-08-16: пользовательских
форм нет, данные в БД не жалеем). Миграция срезает четыре ключа из `forms.schema` и
`form_versions.schema` — формы остаются валидными, условия в них исчезают.

Так дешевле на порядок, чем перенос: конвертер обязан был бы вставлять блок перед каждой
группой-целью, соблюдать `MaxBlocks`, разбирать `jumpIf` в список действий и быть
идемпотентным — сотни строк одноразового кода ради правил, которых никто не писал.

Снос, а не оставление как есть: поля уходят из Zod и Go строгими объектами, и документ с
`visibleIf` перестал бы читаться вовсе — форма в кабинете открылась бы ошибкой.

> Правило действует, **пока форм нет**. Появятся пользователи — этот раздел перестаёт быть
> верным, и следующая ломающая правка формата пишет конвертер.

## 8. Строки ADR §10

**Отменяются:**

1. «Носитель `visibleIf` — головной блок группы» — правило переезжает в блок `logic`,
   голова группы остаётся **адресом цели**, а не носителем.
2. «`required` и `requiredIf` взаимоисключающи» — `requiredIf` как поле исчезает; флаг и
   действие складываются по ИЛИ, конфликт ловится предупреждением (§3.3).
3. «Переходы — носитель `page_break`» в части носителя (правило «только вперёд» остаётся).
4. Формулировка «`schemaVersion` остаётся 4» — правится на «заморожена на 1 до релиза».

**Вносятся:**

5. Условная логика живёт **блоком полотна**; вход в неё один. Отвергнуто: строка-вид поверх
   носителей, позиционная императивная семантика, отдельная сущность «правила формы» (§2.3).
6. **Инертность меряется у ЦЕЛИ:** источник обязан быть выше неё, позиция блока не важна
   (кроме перехода и «скрыть кнопку», у которых цель — страница). Нарушение — инертность,
   а не отказ схемы (§3.1).
7. **Видимость цели считается двумя корзинами** `shows`/`hides` по формуле §3.2 — результат
   не зависит от порядка блоков `logic`.
8. **«Скрыть кнопку» завершает обход** на своей странице; сервер отвечает **422** на попытку
   отправки заблокированной формы (§3.4).
9. Правила из существующих документов **сносятся миграцией, а не конвертируются** — пока
   пользовательских форм нет (§7).

## 9. Риски

| Риск | Как ловим |
|---|---|
| Цель или источник уехали за границу позиции при драге — правило молча умерло | Предупреждение в блоке (§5.3) + тест на каждую причину инертности |
| Расхождение Go и TS в компиляции действий | Одинаковые таблицы кейсов + паритет действий машинным тестом |
| Селекты Radix внутри строки полотна ломают клавиатурный поток строки | Юниты happy-dom селекты не открывают (`EDITOR.md` §15.6) — проверка в браузере и e2e обязательны |
| Миграция испортила формы, которые правилами не пользовались | Срезаются четыре ключа, больше ничего; тест на документе без правил — байт в байт тот же JSONB |
| Форма без логики поехала | Регресс на три поверхности: документ без блоков `logic` ведёт себя байт в байт как до работы |
| Полотно перерисовывается от подписки на `s.blocks` в строке блока | Подписка только на свою строку и свои цели, замер `perChar.scriptMs` (`e2e/perf/results/*.json`), а не время задачи |

## 10. Слайсы

Каждый заканчивается зелёными `make lint && make test` и оставляет продукт целым.

0. **Спека и ADR.** Этот файл согласован, строки §8 внесены в `ARCHITECTURE.md`.

## 11. Критерий приёмки

> На полотне из slash-меню вставляется блок «Условие». В нём выбирается вопрос-источник,
> оператор, значение и действие с целью. Опубликованная форма ведёт себя ровно так, как
> описано блоками: спрятанный вопрос не приходит респонденту, условно обязательный не
> пропускает пустым, ветка уводит на нужную страницу, заблокированная страница не даёт
> отправить (и `curl` мимо неё получает 422). Форма, собранная до переезда, открывается в
> редакторе с теми же правилами — уже показанными блоками — и ведёт себя как раньше.
> Форма без логики не отличается от сегодняшней ни на одной из трёх поверхностей.
