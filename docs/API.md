# Справочник API

Производная справка «как вызывать» по эндпоинтам, реализованным на текущий момент (healthz, аутентификация, CRUD форм, публикация и публичная выдача формы). **Источник истины — `docs/ARCHITECTURE.md`** (модель, контракт, «почему»); при расхождении побеждает он, а эта справка правится в том же PR, что и код. Приём ответов на публичные формы появится в фазе 5 и будет описан здесь тогда же.

## Общие правила

- **Базовый префикс приватного API:** `/api/v1`. В dev Vite проксирует `/api → :8080` (CORS не нужен).
- **Формат:** запрос и ответ — JSON (`Content-Type: application/json`). Тело каждого эндпоинта ограничено `MaxBytesReader`: auth — 4 КБ, forms — 64 КБ (`PATCH` несёт весь `draft_schema` автосейва; внутренние лимиты документа стережёт `ValidateSchema`).
- **Идентификаторы** в путях и телах — UUIDv7-строки; `slug` формы — nanoid из 10 символов.

### Аутентификация и сессия

- После `register`/`login` сервер ставит две cookie: `session` (httpOnly, `SameSite=Lax`, флаг `Secure` — из конфигурации: в dev по http выключен) и `csrf_token` (читаемая JS).
- Приватные эндпоинты требуют живой сессии (`session` cookie). Промах — `401 unauthorized` (не 403: существование ресурса не раскрывается).
- **CSRF (double-submit):** мутирующие запросы (`POST`/`PATCH`/`DELETE`) обязаны прислать заголовок `X-CSRF-Token`, равный значению cookie `csrf_token`. Несовпадение — `403 forbidden`.
- Браузерный `fetch` должен идти с `credentials: 'include'` (в кабинете это делает `shared/api/client.ts`).

### Формат ошибок

Любой не-2xx ответ — единый конверт:

```json
{ "error": { "code": "validation_failed", "message": "…", "fields": { "title": "…" } } }
```

`fields` присутствует не всегда (карта «поле → сообщение» для валидации). Тела 5xx не раскрывают внутренний текст (в логах он есть, с request_id).

| HTTP | `code`                | Когда |
|------|-----------------------|-------|
| 401  | `unauthorized`        | нет живой сессии |
| 401  | `invalid_credentials` | неверный email или пароль (одинаковое время ответа с «нет такого email») |
| 403  | `forbidden`           | не прошёл CSRF-проверку |
| 404  | `not_found`           | ресурс не найден **или** нет доступа (анти-IDOR: не 403) |
| 409  | `email_taken`         | повторная регистрация на занятый email |
| 409  | `conflict`            | оптимистичная блокировка: присланный `updatedAt` устарел (форму изменили в другой вкладке) |
| 422  | `validation_failed`   | невалидное тело/параметры (детали — в `fields`) |
| 429  | `rate_limited`        | сработал лимит (сейчас — на `POST /auth/login`); заголовок `Retry-After` |
| 500  | `internal`            | внутренняя ошибка |

### Пагинация

Курсорная: `?cursor=<непрозрачный токен>&limit=<n>` (`limit` по умолчанию 50, максимум 100). Ответ листаемого эндпоинта содержит `nextCursor` (`null` на последней странице) — его значение передаётся в `?cursor` следующего запроса. Токен непрозрачен для клиента.

## Аутентификация — `/api/v1/auth`

Объект пользователя во всех ответах:

```json
{ "id": "019f…", "email": "user@example.com" }
```

### `POST /auth/register`
Регистрация. Создаёт пользователя, личный воркспейс и членство одной транзакцией, открывает сессию.
- **Тело:** `{ "email": string, "password": string }` (пароль 8–128 символов).
- **200/201:** `201` + объект пользователя; ставит cookie `session` и `csrf_token`.
- **Ошибки:** `409 email_taken`, `422 validation_failed`.

### `POST /auth/login`
Вход. **Rate limit по IP** (≈5 попыток, пополнение ~1 / 12 c).
- **Тело:** `{ "email": string, "password": string }`.
- **200:** объект пользователя + cookie.
- **Ошибки:** `401 invalid_credentials`, `429 rate_limited`.

### `POST /auth/logout`
Требует сессии + CSRF. Удаляет сессию и гасит cookie. **204** без тела.

### `GET /auth/me`
Требует сессии. **200** + объект текущего пользователя. Используется гардом кабинета.

## Формы — `/api/v1/forms`

Все эндпоинты требуют сессии; мутации — ещё и CSRF. Каждый по ресурсу проверяет членство в воркспейсе формы: чужая или несуществующая форма → `404 not_found`.

Объект формы (`Form`):

```json
{
  "id": "019f…",
  "title": "Опрос клиентов",
  "slug": "59LfFK0F4X",
  "status": "draft",                 // draft | published | closed
  "createdAt": "2026-07-11T18:33:43.335082+03:00",
  "updatedAt": "2026-07-11T18:33:43.335082+03:00",
  "publishedVersion": null,          // номер опубликованной версии | null
  "publishedVersionId": null,        // id опубликованной версии | null
  "hasUnpublishedChanges": false     // черновик разошёлся с опубликованной версией
}
```

`publishedVersion`/`publishedVersionId` — `null`, пока форму не публиковали. После `closed` сохраняются (кабинет показывает «была версия N»).

`hasUnpublishedChanges` — `true`, когда черновик формы отличается от опубликованной версии (сравнение `draft_schema` со снапшотом; переименование, не входящее в версию, его не поднимает). **Точен на `GET /forms/{id}` и `GET /forms`;** в ответах мутаций (create/publish/unpublish/rename) всегда `false` — актуальное значение кабинет берёт из `GET`.

### `GET /forms`
Список форм личного воркспейса, свежие правки сверху. Курсорная пагинация.
- **Параметры:** `cursor?`, `limit?` (1–100, дефолт 50).
- **200:**
  ```json
  { "forms": [ /* Form */ ], "nextCursor": "eyJ…" }   // nextCursor: string | null
  ```

### `POST /forms`
Создать форму с пустым черновиком (`{"blocks":[]}`).
- **Тело:** `{ "title"?: string }` (≤200 символов; пусто/нет тела → `"Untitled form"`).
- **201:** объект `Form`.
- **Ошибки:** `422 validation_failed` (title длиннее лимита).

### `GET /forms/{id}`
Форма целиком, включая черновик схемы.
- **200:** `Form` + поле `draftSchema` (JSON черновика; в фазе 2 — `{"blocks":[]}`).
- **Ошибки:** `404 not_found`.

### `PATCH /forms/{id}`
Переименование **или** автосейв черновика схемы. Требует CSRF. За один запрос меняется **ровно одно** из `title`/`draftSchema`:

- **`{ "title": string }`** — переименование (непустой, ≤200 символов); без оптимистичной блокировки, как в фазе 2.
- **`{ "draftSchema": <схема>, "updatedAt": string }`** — автосейв билдера. `draftSchema` — документ формы (контракт — `docs/SCHEMA.md`), проходит строгую валидацию `ValidateSchema` и пишется канонизированным. `updatedAt` **обязателен**: значение, полученное в последнем ответе по форме; сервер обновляет строку, только если оно совпадает с текущим (оптимистичная блокировка).

- **200:** обновлённый `Form` (в т.ч. новый `updatedAt` — использовать как токен для следующего сохранения).
- **Ошибки:** `404 not_found`; `409 conflict` (устаревший `updatedAt`); `422 validation_failed` (пустой/длинный title; невалидная схема; `draftSchema` без `updatedAt`; оба поля сразу или ни одного).

### `DELETE /forms/{id}`
Удаление формы (каскадно уносит версии и, позже, ответы). Требует CSRF.
- **204** без тела.
- **Ошибки:** `404 not_found`.

### `POST /forms/{id}/publish`
Публикация: одной транзакцией снимает иммутабельный снапшот текущего черновика в новую версию (`version = max+1`, счёт с 1), переводит форму в `published` и привязывает эту версию. Черновик перед снапшотом валидируется `ValidateSchema`. Повторная публикация (в т.ч. после `closed`) даёт следующий номер версии. Требует CSRF, тела нет.
- **200:** обновлённый `Form` (`status: "published"`, `publishedVersion`/`publishedVersionId` заполнены).
- **Ошибки:** `404 not_found`; `422 validation_failed` (черновик не проходит `ValidateSchema`).

### `POST /forms/{id}/unpublish`
Снятие с публикации: `status='closed'`. `publishedVersion`/`publishedVersionId` **сохраняются** (последняя опубликованная версия). Требует CSRF, тела нет.
- **200:** обновлённый `Form` (`status: "closed"`).
- **Ошибки:** `404 not_found`.

## Публичные формы — `/public/v1`

Без авторизации и CSRF. Отдаётся **только опубликованная** версия: черновик, закрытая и несуществующая форма неотличимы — все дают `404 not_found` (приватное не раскрывается, инвариант безопасности 5).

### `GET /public/v1/forms/{slug}`
Схема опубликованной версии формы по её `slug` — для публичного рендерера.
- **200:**
  ```json
  {
    "title": "Опрос клиентов",
    "version": 2,                       // номер опубликованной версии
    "schema": { "schemaVersion": 1, "blocks": [ /* ... */ ] },
    "token": "1752307200000.Yk9f…"      // подписанное время выдачи (антиспам, фаза 5)
  }
  ```
  - **Заголовки:** `Cache-Control: public, max-age=60`; `ETag` = id опубликованной версии (иммутабелен, меняется при переиздании). Запрос с `If-None-Match`, совпавшим с текущим `ETag`, → **304 Not Modified** без тела.
  - `token` — HMAC-подпись времени выдачи (ключ `FORM_TOKEN_SECRET`); проверяется при приёме ответа (фаза 5): слишком быстрый ответ — бот.
- **Ошибки:** `404 not_found` (черновик / закрытая / нет формы).

### `GET /r/{slug}`
HTML-документ страницы формы — «голова на сервере, тело на клиенте». Отдаёт **Go** (не статика): краулеры превью читают HTML без JS, поэтому OG-мета подставляется на сервере. `<head>` содержит `og:title` (title формы), `og:description` (тизер из заголовков первых блоков-вопросов), `og:image` (env `OG_IMAGE_URL`, общая заглушка) и `og:url` (`{PUBLIC_RENDERER_BASE_URL}/r/{slug}`); `<body>` — `<div id="root">` + модуль-скрипт, грузящий SPA-рендерер. Пользовательский текст экранируется `html/template` (инъекция `"><script>` в title обезврежена). *(Реальные собранные ассеты и роутинг Caddy — фаза 7; сейчас скрипт указывает на dev-рендерер.)*
- **200:** `text/html; charset=utf-8`, `Cache-Control: public, max-age=60`.
- **Ошибки:** `404 not_found` (черновик / закрытая / нет формы — как и JSON-ручка).
