## Где находится разработка

**Фаза 11 «Вход через Яндекс ID» закрыта.** Что она дала: таблица `user_identities`, модуль
`internal/oauth` (authorization code + PKCE на stdlib, без новых зависимостей), четыре эндпоинта,
кнопка провайдера и экран привязки в кабинете.

**Ключевое решение фазы, о котором надо помнить при работе с входом:** автосвязывания аккаунтов
по email **нет**. Ни Яндекс, ни VK не сообщают, подтверждён ли адрес (`verified` у VK — про
верифицированный профиль, а не про почту), поэтому совпадение email требует разового ввода пароля.
Обоснование — ADR §10 [`ARCHITECTURE.md`](ARCHITECTURE.md).

**Следующая фаза — почта:** транзакционный провайдер, outbox, уведомление владельцу о новом ответе,
сброс пароля, подтверждение email. Развёрнутое описание — [`POST-MVP.md`](POST-MVP.md) (раздел
«Транзакционная почта и восстановление пароля»). Договорённость по outbox уже принята и записана
там же врезкой: событие домена и попытка доставки — разные сущности (канал колонкой), реализуется
один транспорт — почта; ADR-строка вносится вместе с кодом.

**Источники задач:** [`POST-MVP.md`](POST-MVP.md), [`BACKLOG.md`](BACKLOG.md) (верхний пункт —
**вход через VK ID**, каркас под него уже построен) и §2 [`TECH-DEBT.md`](TECH-DEBT.md). У задач
вне фаз готового критерия приёмки нет — он формулируется и согласуется с владельцем до кода
([`PROCESS.md`](PROCESS.md) §1.0).

## Состав системы

- **Go-API** — один бинарник, Go 1.26, 16 модулей в `internal/`
  (`auth`, `blob`, `config`, `domain`, `forms`, `httpserver`, `media`, `oauth`, `periodic`,
  `pgtest`, `postgres`, `ratelimit`, `submissions`, `token`, `visits`, `workspaces`).
- **PostgreSQL 16** — 9 миграций (`0001`…`0009_oauth_identities`). Таблицы — [`SCHEMA.md`](SCHEMA.md).
- **web/app** — кабинет: React + TanStack + Tailwind v4 + shadcn/ui.
- **web/renderer** — публичный рендерер: react + zod, **бюджет 95 КиБ gzip** (сейчас ~81 КиБ).
- **e2e** — три Playwright-сценария против prod-local: `full-loop`, `form-settings`, `visits-funnel`.
- **Эксплуатация** — бэкапы БД в Yandex (`deploy/backup.sh` в cron, восстановление
  `deploy/RESTORE.md`), внешний мониторинг UptimeRobot, ротация docker-логов.

Схема формы — JSONB, `schemaVersion: 2` (вопрос = группа блоков). Контракт API — [`API.md`](API.md).

## Хвосты, за которыми надо следить

- **Учебное восстановление «не подглядывая»** — владелец повторяет сам (финальный DoD фазы 10).
- **Мониторинг на free-тарифе** — 5 мин / email; поднять до Telegram + 1 мин до живых пользователей.
- **PAT сервера истекает ~2026-10-19** — после этого автодеплой падает на шаге деплоя до перевыпуска.
- **Два приложения Яндекс ID** — dev и прод, у каждого свой Redirect URI и свой секрет.
  Прод-ключи живут только в серверном `.env`, dev-ключи — в локальном `.env` разработчика.
  Redirect URI обязан совпадать байт в байт с `<APP_ORIGIN>/api/v1/auth/oauth/yandex/callback`.
- **Регион S3 (`ru-1`) выбран наугад** и подтверждён только тем, что загрузка работает.
- **Бакет медиа открыт на чтение вручную** в панели провайдера (`createbuckets` — только для MinIO).
- **Бакет бэкапов Yandex — приватный**, ключ age-восстановления живёт офлайн у владельца.
- **Ночной e2e** может краснеть от правок редактора: через билдер кликами ходит только `full-loop`.
- **Осиротевший стек `trierra-prod-local`** — контейнеры от старого имени проекта (до
  переименования в `trillix`) висят на машине владельца: api в рестарт-цикле, caddy умер.
  К текущему `make prod-local` отношения не имеют — он поднимается и проходит смоук, e2e
  на нём зелёные. Убрать: `docker compose -p trierra-prod-local down`.

## Что решено НЕ делать сейчас

Перенесено в POST-MVP решением владельца: шаблоны форм, embed + QR, тёмная тема рендерера,
колонки первых вопросов в таблице ответов, UI дубликации блока. Богатый текст в блоках — решение
не принято, ограничения посчитаны ([`TECH-DEBT.md`](TECH-DEBT.md) §5).
