## Где находится разработка

**Фаза 10 «Эксплуатационная зрелость» закрыта — это последняя фаза `DEV-PLAN.md`, MVP (фазы 0–10)
завершён.** Что дала фаза 10: бэкапы БД в Yandex Object Storage (cron `pg_dump` → age → S3 другого
провайдера) с проверенным восстановлением; внешний мониторинг аптайма (UptimeRobot) с алертом;
ротация docker-логов и паттерн маршрута в сводной строке запроса; замер нагрузочного потолка. Разбор
по шагам и принятые решения — [`JOURNAL.md`](JOURNAL.md) «Фаза 10».

**Хвосты фазы 10, которые НЕ закрыты кодом и переезжают вперёд** (не блокеры, но забывать нельзя):

- **финальный DoD восстановления** — владелец повторяет восстановление из бэкапа сам, «не подглядывая»
  по [`deploy/RESTORE.md`](../deploy/RESTORE.md), спустя ~неделю. Первый прогон (при участии) прошёл.
- **поблажки мониторинга** — UptimeRobot free: интервал 5 мин и email вместо Telegram (Telegram платный),
  алерт ~5–10 мин вместо ≤2. Пересмотреть до выдачи живым пользователям (платный тариф или Uptime Kuma).
- **TD-21 не измерен** — нагрузочная проба шла по `/healthz`, а не по приёму ответа (с одного IP лимитер
  не даёт создать конкуренцию на advisory-lock); корректный замер требует prod-local с пермиссивным лимитером.

**Следующие задачи приходят не из плана, а из трёх источников:** [`POST-MVP.md`](POST-MVP.md) (фазы с готовыми
демо-критериями, разворачиваются в `DEV-PLAN.md` перед стартом), [`BACKLOG.md`](BACKLOG.md) (верхний пункт =
приоритет) и §2 [`TECH-DEBT.md`](TECH-DEBT.md). У задач вне фаз готового критерия приёмки нет — он
формулируется и согласуется с владельцем до кода ([`PROCESS.md`](PROCESS.md) §1.0). Что из трёх — вопрос
приоритета, спрашивается у человека.

Функционально MVP полон: сборка формы → публикация → приём ответов → таблица/CSV/сводка/воронка,
плюс эксплуатационный слой (бэкапы, мониторинг, ротация логов). Закрытые фазы — [`JOURNAL.md`](JOURNAL.md).

## Состав системы

- **Go-API** — один бинарник, Go 1.26, 15 модулей в `internal/`
  (`auth`, `blob`, `config`, `domain`, `forms`, `httpserver`, `media`, `periodic`, `pgtest`,
  `postgres`, `ratelimit`, `submissions`, `token`, `visits`, `workspaces`).
- **PostgreSQL 16** — 8 миграций (`0001`…`0008_form_visits`). Таблицы — [`SCHEMA.md`](SCHEMA.md).
- **web/app** — кабинет: React + TanStack + Tailwind v4 + shadcn/ui.
- **web/renderer** — публичный рендерер: react + zod, **бюджет 95 КиБ gzip** (сейчас ~81 КиБ).
- **e2e** — три Playwright-сценария против prod-local: `full-loop`, `form-settings`, `visits-funnel`.
- **Эксплуатация** — бэкапы БД в Yandex (`deploy/backup.sh` в cron, восстановление `deploy/RESTORE.md`),
  внешний мониторинг UptimeRobot, ротация docker-логов (`x-logging` в `compose.prod.yml`).

Схема формы — JSONB, `schemaVersion: 2` (вопрос = группа блоков). Контракт API — [`API.md`](API.md).

## Хвосты, за которыми надо следить

- **Учебное восстановление «не подглядывая»** — владелец повторяет сам через ~неделю (финальный DoD фазы 10).
- **Мониторинг на free-тарифе** — 5 мин / email; поднять до Telegram + 1 мин до живых пользователей.
- **PAT сервера истекает ~2026-10-19** — после этого автодеплой падает на шаге деплоя до перевыпуска токена.
- **Регион S3 (`ru-1`) выбран наугад** и подтверждён только тем, что загрузка работает.
- **Бакет медиа открыт на чтение вручную** в панели провайдера (`createbuckets` — только для MinIO).
- **Бакет бэкапов Yandex — приватный**, ключ age-восстановления живёт офлайн у владельца (не на сервере).
- **Ночной e2e** может краснеть от правок редактора: через билдер кликами ходит только `full-loop`.
