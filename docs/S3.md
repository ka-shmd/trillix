# Работа с объектным хранилищем (S3)

Практический справочник: как у нас устроено объектное хранилище и как с ним
работать. **Живой документ** — пополняется по мере работ по S3 (новый потребитель,
новый бакет, presigned-поток и т.п.).

**Это производный справочник, а не источник истины.** При конфликте побеждает
[`ARCHITECTURE.md`](ARCHITECTURE.md) (ADR §10 — ключевые решения). Здесь — «как оно
работает и как расширять»; **это правда о сегодняшнем дне**, и при расхождении с архивной
спекой [`design/s3-media.md`](design/s3-media.md) (почему так спроектировано) правда здесь.

Смежные документы: [`POST-MVP.md`](POST-MVP.md) — фаза 17 (файлы в ответах, presigned) и
фаза 10 (бэкапы, другой провайдер); [`TECH-DEBT.md`](TECH-DEBT.md) TD-16/TD-17 и §5
(известные гэпы и границы). **Номера фаз здесь — по `POST-MVP.md`;** одноимённые номера
`DEV-PLAN.md` означают другие работы (там фаза 17 — тарифы, закрыта).

## 1. Ментальная модель: два слоя

S3 — это не «одна свалка», а объекты с **несовместимыми политиками** (public
картинки vs private файлы ответов vs бэкапы; см. таксономию в `design/s3-media.md`
§3). Поэтому — два слоя:

- **Слой 1 — транспорт: `internal/blob`.** Провайдеро-агностичный S3-клиент. Говорит
  S3 HTTP + sigv4, знает `Put/Get/Delete/CreateBucket`, **не** знает слов
  «картинка»/«форма». Один на всё приложение.
- **Слой 2 — доменные хранилища.** Тонкие обёртки, каждая владеет своей политикой
  (bucket/prefix, видимость, схема ключей, правила Content-Type). Сейчас один —
  `internal/media` (картинки блоков). Фаза 17 `POST-MVP` добавит хранилище файлов ответов.

**Ключевой принцип (конвенция `internal/CLAUDE.md`): интерфейс объявляет
потребитель.** Слой-1 отдаёт конкретный `*blob.Client` с полным набором методов; а
доменный сервис объявляет **узкий** интерфейс того, что ему нужно, — не тянет весь
клиент. Так нет god-интерфейса, всё мокается, и потребители не пухнут друг от друга.

```go
// в пакете сервиса-потребителя
type blobPutter interface {
    PutObject(ctx context.Context, bucket, key string, data []byte, contentType string) error
}
```

**Провайдеро-независимость.** И MinIO (dev/prod-local), и арендованное S3 (реальный
прод) говорят на одном протоколе. Различие контуров живёт **только в env**
(`S3_*`), код один. Приложение к хранилищу на старте **не** подключается —
недоступный S3 роняет только загрузки, не процесс (liveness не привязан к S3).

## 2. Слой 1 — клиент `internal/blob`

- **`blob.Config`** — `Endpoint` (scheme://host[:port], без пути), `Region`
  (регион подписи; MinIO игнорирует значение, но подпись его включает — `us-east-1`),
  `AccessKey`, `SecretKey` (**секрет, не логируется**), `PathStyle` (bool: `endpoint/
  bucket/key`; MinIO и часть РФ-провайдеров требуют `true`, AWS virtual-hosted —
  `false`).
- **`blob.New(cfg) *Client`** — потокобезопасен (иммутабелен после создания).
- **Методы:** `PutObject(ctx, bucket, key, data []byte, contentType)`,
  `GetObject(ctx, bucket, key) ([]byte, contentType, error)`, `DeleteObject(...)`,
  `CreateBucket(...)` (идемпотентен; в проде бакеты заводит init-`mc`, метод нужен
  тестам/бутстрапу).
- **Ошибки:** `blob.ErrNotFound` (404 → сентинел, чтобы потребитель отличал «нет
  объекта» от транспортной ошибки); прочее — обёрнутая ошибка со статусом.
- **Подпись:** AWS Signature V4 руками (`sign.go`) — без SDK (нужны только
  Put/Delete; публичное чтение идёт голым URL без подписи). Ключи объектов ограничены
  S3-безопасными символами (unreserved + `/`), чтобы `EscapedPath` net/http и наш
  `uriEncode` совпадали.

**Отложено до потребителя (YAGNI):** `Presign` (presigned-поток фазы 17 `POST-MVP`),
`HeadObject` (дедуп-скип), `ListObjects` (GC сирот, TD-16). Добавлять вместе с первым
использующим кодом + интеграционным тестом.

## 3. Слой 2 — доменное хранилище (образец: `internal/media`)

`internal/media` — приём и хранение картинок форм, первый потребитель слоя-1.

- **`media.Service`** держит `blobPutter`, коллаборатора `Forms` (узкий интерфейс над
  `forms.Service` — авторизация членства + `WorkspaceID`) и имя бакета.
- **`Upload(ctx, userID, formID, data, purpose) (imageKey, error)`** — порядок: сначала
  проверка доступа (`forms.Get` → 404 для чужой формы, инвариант 1), потом обработка
  байтов (валидация → гард размеров → **даунскейл → выбор формата** → ре-энкод),
  затем `PutObject`.
- **Даунскейл: кап ШИРИНЫ, пропорции сохраняются, только вниз** (что уже уже
  потолка — не трогается). Кап по ширине, а **не** по длинной стороне: последний
  срезал бы ширину высокого портрета и сделал бы картинку недоразрешённой для той же
  колонки. Числа выведены из вида страницы, а не выбраны на глаз:

  | `Purpose` | Потолок | Откуда число |
  |---|---|---|
  | `block` (дефолт) | `MaxImageWidth` = 1400 | колонка 700 CSS-px (`.rf-page`) × 2 под retina; `.rf-image` — `max-width:100%`/`height:auto`, отображение ограничивает только ширину |
  | `cover` | `MaxCoverWidth` = 2000 | обложка тянется во всю ширину **окна**, а не колонки: ноутбук 1440–1680 CSS-px. Полный ретина-десктоп (2880) сознательно не даём — обложка декоративна, лишние мегабайты у респондента дороже её резкости |
  | `logo` | `MaxLogoWidth` = 512 | логотип рисуется ~72 CSS-px (`.rf-logo`): сегодня хватило бы 216 (DPR 3), запас не стоит ничего — плоская графика в этих габаритах весит единицы КиБ |

  **Назначение — параметр запроса, а не догадка по размеру входа:** обложку от
  картинки блока по пикселям не отличить. Неизвестное значение отвергается на границе
  (`ParsePurpose` → 422), потому что молчаливый откат к `block` дал бы обложку,
  ужатую до ширины колонки, — дефект, который виден только глазами и только потом.
  **Хранилище от назначения не зависит:** тот же бакет, та же политика, тот же
  контент-адресный ключ; назначение в ключ не подмешивается. Одна картинка под двумя
  назначениями даёт два объекта — у них разное содержимое (разная ширина).
- **Формат выбирается по содержимому, не по формату входа.** Есть полупрозрачные
  пиксели → PNG (JPEG не умеет альфу); непрозрачная → кодируется обоими и берётся
  меньший результат. Так фотография, присланная как PNG, уезжает в JPEG, а плоская
  графика и логотипы остаются PNG без потерь, и подбираемого на глаз порога не
  возникает. Порядок величин на реалистичном фото 4032×3024: 1587 → 65 КиБ.
- **Handler:** `POST /api/v1/forms/{id}/media` за `RequireAuth`+`RequireCSRF`,
  `MaxBytesReader` на теле, multipart-поля `file` и необязательное `purpose`, ответ
  `{ "imageKey": "…" }`.

Что взять за образец при новом хранилище: узкие интерфейсы у потребителя;
валидация/обработка **до** записи; контент-адресный ключ; ошибки через доменные
сентинелы (`domain.ErrValidation`/`ErrTooLarge`) → `respond.go`.

## 4. Конфигурация (env)

Все — обязательные (в dev указывают на локальный MinIO). По конвенции
`internal/CLAUDE.md`: новая переменная = поле `config.Config` + `.env.example` +
валидация в `Load` + значения в `.env.dev` и `.env.prod-local`, всё одним коммитом.

| Env | Поле `config.Config` | Назначение |
|---|---|---|
| `S3_ENDPOINT` | `S3Endpoint` | endpoint хранилища (http(s), без пути) |
| `S3_REGION` | `S3Region` | регион подписи sigv4 (MinIO: `us-east-1`) |
| `S3_ACCESS_KEY` | `S3AccessKey` | ключ доступа |
| `S3_SECRET_KEY` | `S3SecretKey` | **секрет** (не логируется; на проде генерируется заново) |
| `S3_MEDIA_BUCKET` | `S3MediaBucket` | бакет public-read картинок (`app-media`) |
| `S3_PATH_STYLE` | `S3PathStyle` | path-style адресация (`true` для MinIO) |

Новый бакет (напр. private `app-uploads` в фазе 17 `POST-MVP`) → своя переменная
`S3_UPLOADS_BUCKET` тем же порядком.

## 5. Бакеты и ключи

- **Бакеты — по видимости** (ACL уровня бакета надёжнее prefix-политик):
  `app-media` (public-read, картинки — сейчас), `app-uploads` (private, файлы ответов
  — фаза 17 `POST-MVP`).
- **`app-media` — public-read без листинга:** анонимный `GetObject` разрешён,
  `ListBucket` — нет (в MinIO — `mc anonymous set download`). Ключ-хэш неугадываем;
  черновиковые картинки технически публичны — принято осознанно (TECH-DEBT §5).
- **Схема ключа:** `<workspace_id>/<sha256(байтов)><ext>` — неймспейс воркспейса под
  будущие per-tenant политики/квоты, внутри — контент-хэш (идемпотентный PUT + дедуп).
- **В схеме формы хранится ключ, не URL** (`settings.imageKey`) — переносимость между
  провайдерами; URL вычисляется (см. §7).

## 6. Локальная инфраструктура (MinIO)

Хранилище локально — **MinIO** контейнером; на реальном проде (фаза 9) заменяется
арендованным S3 сменой только `S3_*` (MinIO тогда не поднимается).

- **dev** (`compose.dev.yml`): сервисы `minio` (порт `127.0.0.1:9000`, консоль `:9001`)
  и одноразовый `createbuckets` (образ `minio/mc`): ждёт MinIO, `mc mb app-media`,
  `mc anonymous set download`. Поднимается через `make dev` / `make dev-all`. Важно:
  `dev-all` держит `createbuckets` **вне** `docker compose up --wait` (одноразовый
  контейнер с exit 0 иначе валит ожидание — см. `scripts/dev-all.sh`).
- **prod-local** (`deploy/compose.prod.yml` + **`deploy/compose.local-media.yml`**):
  `minio` без публикации порта (только внутренняя docker-сеть; `api` ходит на
  `http://minio:9000`) и тот же `createbuckets`. Оба живут **в override-файле**, который
  подключается вторым `-f` только в `make prod-local` (`PROD_COMPOSE`). Базовый
  `compose.prod.yml` описывает ровно прод и этих сервисов не содержит — на реальном
  проде хранилище арендованное. Общие сервисы (api, caddy, postgres, migrate) описаны
  один раз в базе, поэтому контурам нечем разойтись.
- **`api` от хранилища НЕ зависит** (`depends_on` — только `postgres` и `migrate`):
  приложение не подключается к S3 на старте, а на проде MinIO не существует —
  жёсткая зависимость мешала бы старту.

Учётки MinIO берутся из `S3_ACCESS_KEY`/`S3_SECRET_KEY` (`MINIO_ROOT_USER/PASSWORD`).

**На реальном проде бакет заводится и открывается на чтение в панели S3-провайдера**,
а не сервисом `createbuckets` (он только для MinIO). Забыть про это — получить `403
AccessDenied` на раздаче `/media` при рабочей загрузке (приватный бакет: Caddy тянет
объект анонимно, ключи наружу не светятся). Нужен public-read на объекты **без листинга**.

## 7. Раздача картинок

- **Разметка картинки** (`web/shared/fields/BlockField.tsx`, её видят превью билдера и
  публичный рендерер; полотно редактора рисует своим `ImageField.tsx`): `loading="lazy"`
  + `decoding="async"`. **Оговорка:** интринсик-размеров у картинки нет, до загрузки её
  высота — ноль, и ленивая загрузка в таком документе скорее всего не срабатывает —
  **TD-51**. Пока он открыт, не считать ленивость действующей.
- **URL — относительный `/media/<imageKey>`**, одинаков на обоих origin
  (`app.localhost` и `f.localhost`) → раздаётся **same-origin**, CSP `img-src 'self'`
  покрывает. Собирается фронтом: `mediaSrc(key)` в `web/shared/fields/media.ts`.
- **prod-local / прод:** сниппет `(media)` в `deploy/caddy/Caddyfile` на обоих сайтах:
  `handle_path /media/*` срезает префикс, `rewrite` добавляет имя бакета
  (`{$S3_MEDIA_BUCKET}`, path-style), `reverse_proxy {$MEDIA_UPSTREAM}` с
  `header_up Host {$MEDIA_UPSTREAM_HOST}`; иммутабельный кэш (ключи контент-адресны).
  Байты идут через Caddy, не Go. Upstream раздачи задаётся env отдельно от доступа
  приложения (`S3_*`): prod-local — `http://minio:9000` / `minio:9000`; реальный
  прод — `https://<арендованный-s3>` / тот же хост (MinIO тогда не поднимается).
  Host обязателен для внешнего path-style S3 (бакет уже в пути) — MinIO его игнорит.
- **dev:** vite-proxy `/media` → `127.0.0.1:9000/app-media/*` в `web/app` и
  `web/renderer` (`vite.config.ts`).
- **CSP:** `img-src 'self' data: blob:` (`blob:` — оптимистичный локальный превью
  билдера через `URL.createObjectURL`). Раздача остаётся same-origin, поэтому CSP
  не трогается даже при внешнем S3 (Caddy проксирует, origin для браузера — свой).

## 8. Безопасность (инварианты)

- Секреты (`S3_SECRET_KEY`) — в конфиг, **не в логи** (инвариант 7). Бэкапы (фаза 10 `POST-MVP`)
  — **другой** провайдер, **отдельные** креды, не переиспользовать.
- Приём: за `RequireAuth` + проверка членства (инвариант 1) + rate limit;
  `MaxBytesReader` на теле (инвариант 3).
- Тип файла — **по сигнатуре содержимого**, не по заголовку/имени; whitelist PNG/JPEG;
  **SVG исключён** (носит скрипт); гард площади (decompression-bomb); **ре-энкод**
  снимает EXIF/GPS.
- Отдача — корректный `Content-Type` (на PUT) + `X-Content-Type-Options: nosniff`;
  листинг бакета выключен.
- **«Байты через Go» — свойство потребителя, не глобальное правило.** Картинки автора
  идут через Go (малы, нужна валидация/ре-энкод); большие недоверенные файлы ответов
  (фаза 17 `POST-MVP`) — presigned-PUT **мимо** Go.

## 9. Тестирование

- **Интеграционные тесты против настоящего MinIO** — эталон корректности sigv4 и
  полного пути (неверная подпись → `SignatureDoesNotMatch`). Тег `integration`, MinIO
  поднимается через `testcontainers-go` **дженерик-контейнером** (образ `minio/minio`,
  без нового модуля-зависимости — как `internal/pgtest` для Postgres):
  - `internal/blob/blob_integration_test.go` — round-trip клиента (create/put/get/
    delete → `ErrNotFound`);
  - `internal/media/integration_test.go` — эндпоинт end-to-end (Postgres+MinIO):
    загрузка→S3→`GetObject`→декод, изоляция воркспейсов (404), не-картинка (422),
    большое тело (413).
- **Хермётично** (без Docker): `internal/blob/sign_test.go` — `uriEncode`, пустой
  payload-хэш, детерминизм цепочки ключа.
- **E2e** (`make prod-local` + Playwright): `e2e/tests/full-loop.spec.ts` грузит PNG
  буфером (`setInputFiles`) и проверяет, что картинка отдаётся с `/media`
  (`naturalWidth > 0`) — сквозная проверка раздачи Caddy→бакет.

Новый потребитель S3 → интеграционный тест против MinIO обязателен (PROCESS §3:
каждый эндпоинт покрыт тестом).

## 10. Как добавить нового потребителя S3 (чек-лист)

1. **Бакет:** переиспользовать существующий или завести новый по видимости
   (public/private). Новый бакет → env `S3_<NAME>_BUCKET` (§4) + бутстрап в
   `createbuckets` (compose.dev/prod) с нужной политикой.
2. **Слой 2:** доменный сервис (по образцу `internal/media`). Объявить **узкий**
   интерфейс над `*blob.Client` у себя; при недостающем методе (`Presign`/`Head`/
   `List`) — реализовать его в `internal/blob` вместе с тестом.
3. **Ключи:** контент-адресные или доменные, но S3-безопасные (unreserved + `/`).
   В доменной сущности хранить **ключ**, не URL.
4. **Безопасность:** авторизация первой строкой; валидация ввода на бэке; секреты не
   логировать; решить «байты через Go или presigned».
5. **Раздача** (если публичная): `/media`-подобный путь в Caddy/vite или presigned-GET
   (private). CSP при новом origin — обновить.
6. **Тест:** интеграционный против MinIO.
7. **Документы:** пополнить §11 (реестр потребителей) здесь; при новом контракте/
   эндпоинте — `API.md`/`SCHEMA.md`; при отступлении — ADR (`ARCHITECTURE` §10).

## 11. Реестр потребителей S3

Пополняется по мере работ.

| Потребитель | Пакет | Бакет | Видимость | Байты через Go? | Статус |
|---|---|---|---|---|---|
| Картинки блоков (лейаут `image`) | `internal/media` | `app-media` | public-read | да (валидация+ре-энкод) | сделано |
| Файлы в ответах респондентов | — | `app-uploads` | private | нет (presigned-PUT) | фаза 17 `POST-MVP` |
| Бэкапы БД | вне API (cron) | другой провайдер | private, шифр. `age` | — | фаза 10 `POST-MVP` |
